# 12 · 随机性设计准则

> 状态：**已定**。随机性是本作的核心卖点之一，也是最容易做坏的地方——本文件给出硬性约束。

## 1. 五条硬规则

### 规则一：随机性只决定过程，不决定胜负

- ✅ 允许："随机对一名敌方人物造成 3 点伤害"
- ❌ 禁止："50% 概率直接消灭目标"、"50% 概率本局获胜"
- 判据：**单次随机结果的极端情况，不应直接导致一方失败。**

### 规则二：随机性必须可读

- ✅ 允许："随机一名敌方人物"
- ❌ 禁止："随机一个效果"（玩家无法预判范围）
- 判据：玩家在使用这张卡前，能说出**所有可能的结果范围**。

### 规则三：随机性有上下限

| 类型 | 约束 |
|---|---|
| 伤害浮动 | ≤ ±20%（例：6 点伤害浮动为 5–7） |
| 随机目标 | 必须在**合法目标集合**内（受架盾、同列等规则约束） |
| 随机召唤位置 | 只能是己方空格 |
| 随机抽牌 | 从牌库随机，不额外增加张数 |

### 规则四：随机性可被对冲

- 至少提供 2–3 张能**降低随机性**的卡（如"指定目标"的战法、"查看牌库顶"的效果）；
- 玩家的站位决策可以**改变随机目标的合法集合**（例如把人物散开，降低被随机命中核心的概率）；
- 判据：**技术好的玩家，长期胜率应显著高于随机决策的玩家。**

### 规则五：开包/抽卡概率必须公示

- 内购开包（若做）必须在游戏内公示各稀有度概率；
- 局内随机（抽牌、随机目标）不需要公示，但必须有保底体验；
- 合规要求见 `docs/00-tech-selection.md` §4（版号与内容红线）。

## 2. 天时 / 地利 / 人和

随机性与协同的三条轴，每条轴都有明确的玩家预期：

| 轴 | 载体 | 玩家可控性 | 情绪 |
|---|---|---|---|
| **天时** | 事件卡、随机事件 | 低（只能选择时机） | "天灾来了，双方都受损" |
| **地利** | 阵型、位置、列 | **高**（每回合的站位决策） | "我守住这条列" |
| **人和** | 羁绊、阵营、主公技 | **高**（构筑阶段决定） | "刘关张同场才够猛" |

**设计意图**：随机性（天时）只占三分之一，另外三分之二由玩家的构筑与站位决定。这样"我为什么输"永远可以归因。

## 3. 随机性分级

| 级别 | 定义 | 本作使用 |
|---|---|---|
| L0 | 完全确定 | ✅ 大部分卡牌 |
| L1 | 有界随机（浮动/随机目标，范围明确） | ✅ 混乱、随机伤害 |
| L2 | 范围随机（随机召唤、随机抽牌） | ✅ 黄巾之乱、草船借箭 |
| L3 | 结构随机（卡组顺序、起手、先手） | ✅ 卡牌游戏固有 |
| **L4** | **单次决定胜负** | ❌ **禁止** |

## 4. 随机性来源清单

| 来源 | 级别 | 玩家可控性 | 说明 |
|---|---|---|---|
| 卡组顺序 | L3 | 构筑可控 | 30 张卡组，曲线设计影响体验 |
| 起手牌 / 抽牌 | L3 | 构筑可控 + 换牌 | 换牌一次 |
| 掷先手 | L3 | 不可控 | 对称 + 后手补偿 |
| 酒令选择 | L3 | **可控**（三选一） | 开局策略 |
| 事件卡 | L1–L2 | 时机可控 | 对称效果，施放者掌握时机 |
| 混乱状态 | L1 | 站位可控 | 目标在合法集合中随机 |
| 随机召唤位置 | L1 | 站位可控 | 只能是己方空格 |
| 随机伤害浮动（若使用） | L1 | 无 | 上限 ±20% |
| **概率性行动失效** | L1 | 站位与时机可控 | **公共特性**（ADR-013）：以公开概率使指定敌方人物一段时间内无法行动。多个武将 / 战法可复用同一机制，不视为设计重合 |

### 4.1 概率性行动失效的约束（ADR-013）

| 项 | 约束 |
|---|---|
| 概率公开 | 必须是**明示的固定概率**（如"一半概率"），不允许隐藏概率 |
| 作用范围 | 只作用于**人物卡**的"行动"，不允许直接作用于主将或直接造成伤害 |
| 持续时间 | 必须**有上限**（通常 1 回合），不允许永久封锁 |
| 为什么不属于 L4 | 单次失效只是**推迟一个动作**，不改变场面归属，也不直接决定胜负（规则一） |
| 与"随机消灭"的区别 | 失效是**可恢复的过程代价**；消灭是**不可逆的结果**，故后者仍在 §5 禁止 |

## 5. 反模式清单（明确禁止）

| 反模式 | 为什么禁止 |
|---|---|
| "掷骰定输赢" | 违反规则一 |
| "随机消灭一个敌方人物" | 极端结果等于直接改变胜负 |
| "随机获得一张牌"但可能获得任意牌 | 不可读，玩家无法预判 |
| 无上限的随机伤害 | 违反规则三 |
| 随机目标可命中主将且伤害高 | 破阵机制被绕过 |
| 抽卡开箱不公示概率 | 合规风险 |

## 6. 与工程实现的对应

| 要求 | 实现 |
|---|---|
| 随机性可复现 | 确定性 RNG + seed（`core` 的 `Rng` 模块） |
| 随机性可测试 | 固定 seed 跑 golden replay，断言最终状态 |
| 随机性可审计 | 每局记录 seed，可用于回放与申诉 |
| 随机性可分析 | 平衡模拟器跑 10 万局，统计胜率与方差 |

> 这也是为什么 `core` 必须是**确定性**的：同一 seed + 同一操作序列 = 同一结果。
