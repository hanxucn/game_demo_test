## 3. 决策记录（ADR）

| 编号 | 决策 | 结论 | 理由 | 日期 |
|---|---|---|---|---|
| ADR-001 | 战场列数 | **5 列 × 2 排** | 主将需"清空一列"才可被攻击，5 列时攻防节奏居中（4 列偏慢、6 列偏快） | 机制设计期 |
| ADR-002 | 架盾与主将的关系 | **方案 A：架盾不阻挡对主将的攻击** | 避免"嘲讽 + 阵型"双层护盾拖慢对局；盾兵保护将士、阵型保护主公，各司其职 | 机制设计期 |
| ADR-003 | 架盾生效条件 | **仅前军生效** | 保留炉石式直觉，同时让"放哪一排"仍是决策 | 机制设计期 |
| ADR-004 | 屏幕方向 | **横屏** | 5×2 战场 + 卡面文字需要横向空间；横屏下卡面可显示关键词文字 | 机制设计期 |
| ADR-005 | 先手决定方式 | **掷点 + 后手传国玉玺** | 早期方案（比统率）会泄露牌库信息 | 机制设计期 |
| ADR-006 | 进化卡与站位 | **进化卡只针对特定兵种，与站位无关** | 进化是兵种形态转换，规则最简、最易数据化 | 机制设计期 |
| ADR-007 | 费用与属性的关系 | **费用绑定总价值，不绑定属性** | 允许"低属性 + 强技能"与"高属性 + 无技能"两条路线 | 机制设计期 |
| ADR-008 | 神射是否绕过架盾 | **不绕过** | 否则盾兵失去意义；神射的价值是"跨列施压" | 机制设计期 |
| ADR-009 | 主将是否参与普通攻击 | **不参与** | 主将定位是统帅，避免"主公互砍" | 机制设计期 |

| ADR-013 | 概率性行动失效的归属 | **是「公共特性」，不是某人物 / 某计谋的专属效果** | 马忠「设伏」与战法「攻心计」同效属**预期设计**：概率使敌方停止行动作为通用机制存在，允许多张卡复用，不按"设计重合"处理 | 2026-09-11 |
| ADR-014 | 主公身份与人物卡的关系 | **主公身份与人物卡解耦，同一人物允许两套卡**：① 第一期标准模式仍固定四主公（曹操 / 刘备 / 孙权 / 董卓）；② 后续开放"选择非指定人物作为主公"；③ 四主公同时需要**普通人物卡**版本；④ **标准模式下，主公的普通卡不得进入可用卡池** | 已有 `data/heroes.yaml` 的四主公（主公技），照片稿中另有曹操 / 刘备的**主公卡**与未来普通卡；三者是不同模式下的不同产物，不能混为一谈 | 2026-09-11 |
| ADR-015 | 谋臣攻击力是否必须为 0 | **暂不强制**：允许一部分谋臣带 1 攻、一部分 0 攻，是否统一归零**待定** | 手写稿 22 张谋臣里 20 张带攻（18 张为 1 攻），与现行硬规则全面冲突。先按设计稿收录，规则结论后置；`core` 校验规则⑤当前会对这些卡报错，规则改法待定 | 2026-09-11 |

| ADR-041 | 第三批通用算子 | 补齐 ① **主公可承载状态**（`Lord.statuses`，`apply_status target:{lord:true}`）+ 能力 `block_lord_skill` / `extra_lord_skill` ② **条件费用规则** `cost_rule`（每次算费用时重新判定）③ **读取被弃牌属性** `value_from_discarded` ④ **事件标记取值** `value_from_flag` ⑤ 新动作 `extra_attack` / `take_control` / `copy_skill` / `force_attack` ⑥ 新时机 `on_card_played` / `on_mark_damaged` / `on_mark_death` ⑦ 新状态 `duan_chou` 断抽 / `jue_dou` 决斗 / `chou_di` 仇敌 / `jin_yan` 进言 / `can_mou` 参谋 ⑧ 光环重算改为**先清后加**（修掉状态累加 bug） | 剩余 14 张卡各自缺一项通用能力；其中光环累加是实测暴露的真 bug——黄权「劝谏」在出牌后被重算两次，参谋叠成 2 层 | 2026-09-12 |
| ADR-039 | 伤害重定向与免死 | **伤害重定向做成通用机制**：被保护者获得带 `redirect_damage` 能力的守护状态，状态记录守护者 uid；`dealDamage` 在免疫判定**之前**查表并整体转移伤害（非分摊），守护者阵亡则回落、递归上限 3 层。同时新增 `on_lethal` 时机与 `survive` 动作实现免死 | 周泰援护、陈宫分担、曹操护驾**机制完全相同**，只是卡面文案不同——做成三套逻辑会重复且易出不一致；免死（周泰/夏侯惇「50% 以 1 血存活」）无法用现有「扣血后触发」表达，因为那时单位已被移出战场 | 2026-09-12 |

| ADR-037 | 光环与属性修正层 | **属性拆成「基础值 + 修正层」两层**；`modify` 不再直接改 `atk`/`maxHp`，而是写入 `Unit.mods`；新增 `kind: aura` 光环技能——其 effects 被"收集"成修正项，在时机表第 3/7/19/21 步**整体重算**。修正层同时承载三类来源：光环(aura) / 临时(temp, 带 turns) / 永久(permanent) | 原实现 `u.atk += d` 加完回不去，导致：① 沙摩柯「场上每有 1 名蛮族 +1/+1」只能算一次，之后新上蛮族不重算 ② 甘宁「-1 攻**一回合**」实际是永久，`modify.duration` 从未实现。两者是同一架构缺口的两个表现 | 2026-09-12 |
| ADR-036 | DSL 第二批算子 | 补齐 `flip` 翻面、`scry` 卡池操作、`adjacent_to` 相邻过滤、`cost_below_source` 相对费用、`value_from` 动态数值、`lord: true` 主帅目标、`on_attack` / `on_damaged` 触发时机。`CardType` 补入 `lord` / `token` / `status` | 逐阵营翻译 119 张卡时暴露：这七项各有多张卡依赖，属通用算子而非个例；`CardType` 缺三种已在数据中使用的类型 | 2026-09-12 |
| ADR-034 | 状态能力机制 | **状态从「层数计数器」升级为「层数 + 剩余回合」，并由能力表驱动行为**：状态定义里声明 `caps`（`block_attack` / `block_skill` / `block_action` / `untargetable` / `random_target` / `immune_debuff` / `immune_damage`），**引擎只查能力、不认状态 id**——新增状态只改数据不改代码。新增 `jin_yong` 禁用 / `mian_yi` 免疫 / `fan_mian` 翻面。持续时间在**持有者回合结束**递减（时机表第 21 步，在 `turn_end` 触发技之后）。另实现 `clash` 拼点（掷点或比统率，结果写 `flags` 供条件读取） | 原实现只有层数、没有持续时间（"持续 1 回合"与"持续 3 回合"等价），且状态行为硬编码在 `rules.ts`/`engine.ts` 里，加一个状态就要改代码——违反"加一张卡只改数据" | 2026-09-12 |
| ADR-035 | 状态递减的时机 | **必须是时机表第 21 步**（`turn_end` 触发技之后），不能并入第 20 步的中毒结算 | 实测踩坑：「持续 1 回合」的混乱若在第 20 步就递减，会在自己的回合结束技生效前被清掉，技能永远看不到混乱 | 2026-09-12 |
