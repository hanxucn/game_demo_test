01 · 总览与设计支柱

1. 一句话定位

一款以三国为背景、5 列破阵为核心机制的阵营卡牌对战游戏。

玩家选择蜀、魏、吴、群雄四阵营之一，以对应主公出战，通过兵种布阵、武将技能、事件与战法卡，击破对方主公。

2. 三条设计支柱

支柱一：规则极简，卡牌承载深度

  • 战场规则只有 4 条（见 §4）；
  • 所有战术深度来自卡牌的关键词、技能与羁绊，而不是规则本身的复杂度；
  • 检验标准：新玩家 3 分钟内理解全部规则，30 局后仍在发现新组合。

支柱二：内容为王

  • 长期留存来自历史人物卡牌、事件卡、战法卡、羁绊组合的质量与数量；
  • 因此内容必须数据驱动：加卡只改数据文件，不改代码；
  • 每张卡必须具备"一句话记忆点"（见 05-cards.md）。

支柱三：破阵斩将的空间感

  • 攻击主将需要清空一整列，让"破阵"成为核心战术目标；
  • 位置（列/排）是真实决策：近战只能打同列、弓箭手可跨列、盾兵只有在前军才挡人；
  • 但位置规则不得超过 4 条，避免认知负荷压过卡牌深度。

失败归因玩家能说清"我为什么输"（随机性可读，见 12-randomness.md）

4. 核心规则一览（4 条）

  1. 近战只能攻击同列：目标列前军为空则打后军，两排皆空则可攻击主将
  2. 前空打后（穿透）：目标列前军为空时，近战可攻击该列后军
  3. 全空打主将：攻击者所在列的两排皆空时，才能攻击敌方主将
  4. 架盾最高优先级：只要场上存在敌方架盾人物，任何普通攻击都必须先打它（可跨列）

5. 天时 / 地利 / 人和：随机性与协同的三条轴

这是本作对"随机性"的框架化处理，也是三国题材最自然的表达。

轴载体作用玩家感知
天时事件卡、随机事件不可控的外部冲击"天灾来了，双方都要受损"
地利阵型、位置、列可控的空间决策"我守住这条列就赢了"
人和羁绊、阵营、主公技长期构筑与组合"刘关张同场才够猛"

三条轴各自有明确的玩家预期，因此失败原因永远可归因——这是随机性设计的第一原则。

  • 排（Row）：前军 / 后军
  • 格（Slot）：(列, 排)，例如 (3, 前军)
  • 同列：双方屏幕位置相同的列，即"正对面"

3.2 攻击目标判定（ADR-051 改版）

按以下优先级顺序判定合法目标：

① 场上存在敌方「架盾」人物卡？
   → 目标只能是架盾人物卡（多个架盾则任选其一）★ 嘲讽
② 否则：可自由选择**敌方任意人物卡**作为目标
   （「翻面」与「奇袭」的单位不可被指定）
③ 并且：**始终可以直接攻击敌方主将**
与旧版的差别：取消了「近战只能打同列」「前军→后军穿透」「必须清空一列才能打主将」
三条规则。现在主将是随时可打的开放目标，唯一的阻挡手段就是「架盾」。
这使对局节奏显著加快——主将 30 血，需要靠架盾与回复维持。

3.3 弓箭手「射箭」

弓箭手默认 0 攻，不通过普通攻击输出，而是靠「射箭」：

项规则
时机回合结束时自动执行（无需玩家操作）
目标随机一名敌方人物或敌方主将（含主将）
效果1 点伤害
多个弓兵每个弓兵各结算 1 次（3 个弓兵 = 3 次随机 1 伤）
架盾可以绕过（设计者裁定，ADR-054）——架盾只拦普通攻击，不拦「射箭」
实现：damage value:1 + target.filter.include_lord: true + mode: random（ADR-051 新增 include_lord）。
旧版「神射：可攻击任意列的人物卡」在单排后已无意义。

3.4 攻击结算顺序

一次普通攻击同时结算（与炉石一致，ADR-062）：

1. 攻击者 → 目标：造成等同于攻击者攻击力的伤害
2. 目标 → 攻击者：同时造成等同于**目标攻击力**的伤害（反击）
   · 只要目标有攻击力就必定反击 —— **哪怕它在这一击中被杀死**
   · 目标攻击力为 0 → 无反击伤害
   · 唯一的免疫途径：攻击者身上有「圣盾」（免疫伤害，触发后消耗一层）
3. 目标为主将 → 主将不反击
4. 伤害结算（护甲/免疫/圣盾等修正）→ 见 `10-skills-statuses.md`
5. 死亡结算：血量 ≤ 0 的人物卡移出战场，触发「忠义/遗计」等亡语
   · 双方都 ≤ 0 → 两张卡同时阵亡
「先攻」与反击无关（ADR-055）：先攻只表示"入场当回合即可行动"，不含
"击杀不遭反击"。早期文档里的这条定义出自初始提交、系 AI 编写，已删除。
「无双」（攻击不受反击）同样已取消（ADR-054）。

4. 主将保护（ADR-051 改版）

项规则
攻击主将的条件无敌方「架盾」人物卡在场即可直接攻击；架盾在场时必须先清掉架盾
为什么单排后没有"阵型纵深"可依托，主将保护改由架盾承担
主将反击无
主将受伤先扣护甲，护甲为 0 后扣生命
主将阵亡生命 ≤ 0 → 该方立即失败
战术推论：主将不再是"打穿一列才能碰到"，而是默认开放。因此：
· 架盾单位是主将的唯一盾牌，价值大幅上升；
· 回复（刘备仁德、华佗青囊）与护甲的防守价值同样上升；
· 对局节奏比旧版快——这是 ADR-051 有意接受的取舍（设计者要求「可以直接攻击主将」）。

⚠️ 平衡风险：8 格铺满时每回合可对主将倾泻全部攻击力（轻松 20+ 点），
主将 30 血可能偏薄。需要实机测试后决定是否上调主将血量或加回复手段（记入 Q-02-x）。

4.1 泄压阀

单排后主将直接暴露，节奏已经很快，因此不再需要旧版的「破阵奖励」：

  1. 计谋直伤：谋臣的主动技、战法卡、事件卡可以直接伤害主将
  2. 粮尽：牌库抽空后，每回合抽牌时受到递增伤害（1、2、3…）
~~破阵奖励（清空一列 +1 攻）~~ 已随「列」的概念一起作废。

5. 架盾（嘲讽，ADR-051 改版）

项规则
生效条件该人物卡带「架盾」关键词即生效（不再限定前军——单排后没有前军）
效果敌方任何普通攻击必须先攻击架盾人物；不给出主将选项
优先级最高（先于自由选目标）
破盾手段① 直接击杀架盾人物；② 谋臣的计略 / 战法 / 事件卡造成的伤害不吃嘲讽
多个架盾存在多个时，攻击者可任选其一作为目标（嘲讽不唯一）
与炉石「嘲讽」一致：架盾在场时，普通攻击既不能越过它打别的将士，也不能打主将。
设计意图：单排后架盾是主将唯一的盾牌，因此它同时也是"保命"手段——
与旧版「架盾不阻挡打主将」相反（旧版主将靠阵型保护，新版只能靠架盾）。

6. 列数权衡（决策记录 ADR-001 → ADR-051 改版）

下面保留当时的权衡记录作为决策存档。

背景

主将可被攻击的条件是"攻击者所在列两排皆空"。防守方要封死所有列，至少需要 N 个单位（N = 列数），而受统率限制，实战场上通常只有 3–6 个单位。

结论

列数封死所需单位节奏倾向
4 列4偏慢、偏控制
5 列（采用）5居中
6 列6偏快、偏铺场
  • 采用 5 列 × 2 排：节奏居中，配合 30 HP + 6–8 分钟目标；
  • "补空列"（lane denial）成为核心技巧：1 费的 2/1 步兵不只是站场，还是堵隘口的工具；
  • 6 列在横屏下 UI 同样可行，作为可选方案保留（若实测对局过慢可改）。

降级预案

若真机测试发现 5 列在部分机型上可读性不足 → 退回 4 列 × 2 排，并把主公生命降至 25 以补偿节奏。

2. 回合结构

回合分为三个阶段，顺序固定：

┌─────────────────────────────────────────────┐
│ ① 回合开始阶段                                │
│   1. 统率值恢复至上限（完整回合结束才双方 +1）    │
│   2. 抽 1 张牌（牌库空 → 触发粮尽，见 §4）      │
│   3. 结算「回合开始」类效果：                    │
│      · 顺序：己方人物卡从左到右、先前军后后军     │
│      · 例：急救回血、陷阵营回血、光环生效、中毒结算 │
├─────────────────────────────────────────────┤
│ ② 行动阶段（自由顺序，无次数限制除下述）          │
│   · 使用卡牌（消耗统率值）                       │
│   · 发起普通攻击（每张人物卡每回合 1 次）          │
│   · 使用主将主动技（每回合 1 次）                 │
│   · 使用酒令效果（按酒令定义）                    │
│   · 顺序完全自由：可先攻击再出牌，也可穿插         │
├─────────────────────────────────────────────┤
│ ③ 回合结束阶段                                 │
│   1. 结算「回合结束」类效果（例：中毒、灼烧）       │
│   2. 清除「本回合」临时效果（例：本回合 +2 攻）     │
│   3. 手牌上限检查：超过 10 张则弃牌至 10 张        │
│   4. 交出行动权给对手                           │
└─────────────────────────────────────────────┘

2.1 为什么不分"出牌阶段 / 战斗阶段"

  • 与炉石一致的自由顺序，学习成本最低；
  • 卡牌游戏的核心乐趣之一是"先攻击再出牌还是先出牌再攻击"的顺序决策；
  • 阶段划分会把这个决策空间砍掉。

2.2 结算顺序的重要性

当多个效果同时触发时，顺序会决定结果（例如"回合开始回血"与"回合开始掉血"的先后）。
完整规则见 10-skills-statuses.md §结算时机表。

3. 主公生命 30 的论证

3.1 为什么 30 是合理的

高费武将的攻击力可以很高（例如 8），而主将保护规则要求"清空一列"才能攻击主将，因此：

30 HP ÷ 8 攻击 = 4 次未受阻挡的攻击
  • 4 次攻击意味着至少 4 个回合的铺垫与破阵，节奏成立；
  • 若主将可被无脑打脸（无阵型保护），对局会退化为"谁先抽到高攻武将"，30 HP 反而不够。

3.2 高攻武将的定位

定位说明
破阵后的收割者需要先清空一列，才能让高攻武将打主将
清场主力8 攻可以一击秒杀绝大多数兵种
需要保护高攻武将通常血不高，容易被计谋/战法针对

  • ✅ 正例："阵亡时对全体敌人造成 2 点伤害"
  • ✅ 正例："只要它在场，我方弓箭手攻击 +1"

3. 两条高费卡设计路线

高费卡（≥6 统率）必须选择以下两条路线之一，不允许"什么都占"：

路线 A：低属性 + 强技能

项说明
属性低于同费白板基准
技能价值高、有决定性影响
代表诸葛亮、周瑜、郭嘉（待填具体数值）

对策① 技能可互动（需铺垫/可被震慑/可被移除）；② 提供保底小收益

项说明

同时拥有高属性与强技能的高费卡，会在所有对局中成为"必带"，压缩构筑多样性。

3. 关键词详解

3.1 忠义

项内容
效果该人物卡阵亡时，触发其描述的亡语效果
触发时机死亡结算后（见 10-skills-statuses.md 结算时机表）
叠加不叠加；每张卡只有一个忠义效果
UI图标：白色羽扇 / 灰色描边
设计注意亡语不能过强，否则"送死流"会成为唯一解

3.2 遗计

项内容
效果该人物卡阵亡时，其控制者抽 1 张牌
与忠义的关系是忠义的固定形态，独立成关键词以便定价与批量产卡
触发时机同忠义
设计注意抽牌价值约 3 属性点，故关键词价值记为 −2（已扣除"需要死亡"的概率折扣）

3.3 疾行

项内容
效果入场当回合即可发起普通攻击
不提供额外攻击次数（本回合仍只能攻击 1 次，除非同时有「连击」）
触发时机入场即获得，永久
设计注意疾行 + 高攻 = 强突进；需控制属性预算

3.4 架盾

项内容
效果敌方任何普通攻击必须先攻击该人物（可跨列）
生效条件仅当该人物位于前军；位于后军则失去架盾
优先级高于同列限制、高于「神射」
对主将不阻挡对主将的攻击
破盾击杀该人物；或使用谋臣计略/战法/事件（计略伤害无视架盾）
UI图标：盾牌；位于后军时图标置灰
设计注意架盾保护的是将士，不是主公；主将由阵型保护

3.5 武圣

项内容
效果免疫一次伤害（无论来源）
消耗免疫一次后关键词消失
触发时机伤害结算前判定
与护甲的区别武圣对该人物卡生效；护甲只对主将生效
设计注意是路线 B（高属性无技能）的"抗解"手段

3.6 神射

项内容
效果可攻击任意列的敌方人物卡，无需同列
限制仍须遵守架盾；攻击主将仍需满足"所在列两排皆空"
不受影响不受"被自己人挡住"限制（可从后军越排攻击）
设计注意神射的价值是"跨列施压"，不是"无视嘲讽"

3.7 连击

项内容
效果每回合可发起 2 次普通攻击
攻击次数每张人物卡每回合默认 1 次，连击提升为 2 次
结算两次攻击分别结算伤害与反击
设计注意连击 + 高攻 = 极高爆发，属性必须显著下调

3.8 饮血

项内容
效果该人物造成伤害时，为己方主将恢复等量生命
治疗上限主将生命不超过 30
不与护甲互动不增加护甲
触发普通攻击、主动技造成的伤害均触发
设计注意饮血在持久战中价值极高，需控制属性

3.9 奇袭

项内容
效果不能被敌方指定为攻击目标
失去条件该人物发起攻击后立即失去奇袭
不受保护仍会被群体伤害（AoE）、事件卡、随机目标效果命中
UI卡面半透明 + 潜行图标
设计注意奇袭 + 高攻 = 无法被先手处理，属性需下调

3.10 先攻

项内容
效果入场当回合即可行动（含攻击），不受召唤失调限制
触发单位入场时判定
与反击的关系无。攻击一律同时结算，打死目标也照样吃它的反击（ADR-062）
设计注意先攻让高攻单位能立刻压场，价值集中在"抢节奏"
历史：早期文档把先攻写成"先结算伤害，目标阵亡则不受反击"。该定义出自
初始提交 3849164、系 AI 编写却被标为「已定」，手写稿中并无依据（ADR-055）。
现已删除，引擎中对应行为也一并移除。

3.11 结阵

项内容
效果若同列或左右相邻列存在 ≥1 名友方步兵，本次普攻 +1 伤害
判定时机每次攻击时动态判定（不改变面板攻击力）
相邻范围同列（前后）+ 左右相邻列（共最多 5 格）
不叠加无论有几个相邻步兵，都只 +1
UI满足条件时卡牌发光 + 图标高亮
设计注意步兵是"集群推进"兵种，鼓励铺阵

3.12 无双

项内容
效果该人物发起普通攻击时，不受到目标的反击伤害
不等于先攻先攻是"抢在反击前结算"；无双是"根本不挨反击"
不提供不免疫主动技/战法/事件造成的伤害
设计注意价值最高的关键词之一，通常只出现在顶级武将上

4. 关键词组合的定价规则

多个关键词同时出现时，总价值 = 各关键词价值之和 × 0.9（折扣系数，避免组合过强）。

例：疾行（−1.5）+ 先攻（−1）= −2.5 × 0.9 = −2.25，向上取整为 −2.5。

状态保留原有 buff / debuff 全部保留
卡牌 ID变为新卡牌 ID（如 shu_infantry → wei_tiger_cavalry）
入场效果不触发（视为形态转换，不是新单位）
攻击次数不重置（若本回合已攻击过，进化后不能再次攻击）
攻击力变化若进化提升了攻击力，当回合已攻击过则不改变已结算的伤害

4.3 进化卡的价值定价

进化卡的价值 = 属性提升 + 关键词获得 − 前置条件折扣。

进化卡属性提升关键词获得原始价值前置折扣净价值3 费基准
虎豹骑+2 点（+1/+1）先攻 −13×0.8（需场上有步兵）2.47 点预算中占 2.4
陷阵营+2 点（+0/+2）回合回血 ≈ −1.53.5×0.82.8同上
白马义从+1 点（+1/0）无双（部分）≈ −1.52.5×0.82.0同上
进化卡的"3 费"是额外投入：玩家需要先有对应兵种（已花 1–2 费），再花 3 费升级。
因此进化卡不能太强，否则"铺兵 + 进化"会成为压倒性的唯一解。当前数值偏保守，需实测。

4.4 为什么进化卡不涉及站位

  • 进化是兵种形态转换，不是位置操作；
  • 玩家关心的是"我场上有这个兵种吗"，而不是"它站在哪里"；
  • 这样进化卡的规则最简（1 条目标限制），也最容易用数据表达。

1. 事件卡：「天道无情」原则

1.1 核心公式

事件卡 = 对双方同时生效的对称效果 + 施放者的时机优势

这是本作对"事件卡"的定义，也是它区别于炉石法术的地方：

  • 天灾人祸不认敌我（灾年、瘟疫、南蛮入侵都伤害所有人）；
  • 但施放者可以选择时机——在自己占优、或对手关键人物残血时引爆；
  • 因此事件卡是"放大器"，不是"解场牌"。

目标通常是"全场"或"某一排"

12 · 随机性设计准则

状态：已定。随机性是本作的核心卖点之一，也是最容易做坏的地方——本文件给出硬性约束。

1. 五条硬规则

规则一：随机性只决定过程，不决定胜负

  • ✅ 允许："随机对一名敌方人物造成 3 点伤害"
  • ❌ 禁止："50% 概率直接消灭目标"、"50% 概率本局获胜"
  • 判据：单次随机结果的极端情况，不应直接导致一方失败。

规则二：随机性必须可读

  • ✅ 允许："随机一名敌方人物"
  • ❌ 禁止："随机一个效果"（玩家无法预判范围）
  • 判据：玩家在使用这张卡前，能说出所有可能的结果范围。

规则三：随机性有上下限

类型约束
伤害浮动≤ ±20%（例：6 点伤害浮动为 5–7）
随机目标必须在合法目标集合内（受架盾、同列等规则约束）
随机召唤位置只能是己方空格
随机抽牌从牌库随机，不额外增加张数

规则四：随机性可被对冲

  • 至少提供 2–3 张能降低随机性的卡（如"指定目标"的战法、"查看牌库顶"的效果）；
  • 玩家的站位决策可以改变随机目标的合法集合（例如把人物散开，降低被随机命中核心的概率）；
  • 判据：技术好的玩家，长期胜率应显著高于随机决策的玩家。

规则五：开包/抽卡概率必须公示

  • 内购开包（若做）必须在游戏内公示各稀有度概率；
  • 局内随机（抽牌、随机目标）不需要公示，但必须有保底体验；
  • 合规要求见 docs/00-tech-selection.md §4（版号与内容红线）。

2. 天时 / 地利 / 人和

随机性与协同的三条轴，每条轴都有明确的玩家预期：

轴载体玩家可控性情绪
天时事件卡、随机事件低（只能选择时机）"天灾来了，双方都受损"
地利阵型、位置、列高（每回合的站位决策）"我守住这条列"
人和羁绊、阵营、主公技高（构筑阶段决定）"刘关张同场才够猛"

设计意图：随机性（天时）只占三分之一，另外三分之二由玩家的构筑与站位决定。这样"我为什么输"永远可以归因。

4.1 概率性行动失效的约束（ADR-013）

项约束
概率公开必须是明示的固定概率（如"一半概率"），不允许隐藏概率
作用范围只作用于人物卡的"行动"，不允许直接作用于主将或直接造成伤害
持续时间必须有上限（通常 1 回合），不允许永久封锁
为什么不属于 L4单次失效只是推迟一个动作，不改变场面归属，也不直接决定胜负（规则一）
与"随机消灭"的区别失效是可恢复的过程代价；消灭是不可逆的结果，故后者仍在 §5 禁止

1. 总价值预算模型

总价值 = 属性点 + 关键词价值 + 技能价值 + 羁绊协同价值 − 负面代价

1.1 为什么不是"费用绑定属性"

费用不绑定属性——高费卡可以是"低属性 + 强技能"，也可以是"高属性 + 无技能"。
费用绑定的是总价值，属性只是其中一个可分配项。

7.6 概率 · 条件 · 动态取值（ADR-033）

设计原则：卡牌效果没有"特殊机制"，只有"通用算子的组合"。
概率 = 掷一次骰子；随机 = 目标集合里随机取；条件 = 结算前查一次局面；
动态取值 = 数一个集合的大小。全部用确定性 RNG，保证回放可复现。

① 概率 chance

任何效果都可加 chance（0–1），结算前掷一次骰子，不中则整个效果跳过。

- action: apply_status
  status: zhen_she
  chance: 0.5                 # 一半概率
  target: { side: enemy, filter: { type: 'character' }, count: 1, mode: 'random' }

② 条件 condition

效果可加 condition，不满足则跳过。四种写法，覆盖卡池全部需求：

# a) exists —— 该集合非空（"当场上有低于 3 统帅的人时"）
condition: { exists: { side: 'both', filter: { type: 'character', cost_max: 3 } } }

# b) count —— 某集合数量与定值比较（"场上只有典韦一名己方人物时"）
condition: { count: { side: ally, filter: { type: 'character' } }, op: '==', value: 1 }

# c) count_vs —— 两个集合数量互比（"对方场上卡牌数不少于己方时"）
condition: { count_vs: { left: { side: enemy }, right: { side: ally }, op: '>=' } }

# d) event —— 本次结算中发生过某事（"如若斩杀敌人"）
condition: { event: killed }        # killed | clash_won | clash_lost

③ 动态取值 value_from

数值不再写死，改为数一个集合（"场上每有 1 名蛮族人物，自身 +1 攻 +1 血"）：

- action: modify
  attack_from: { side: 'both', filter: { tag: man_zu } }      # +1 × 蛮族人物数
  health_from: { side: 'both', filter: { tag: man_zu } }

*_from 的取值 = 该选择器命中的单位数 ×（可选）per 系数；也支持 limit 上限。

7.7 光环与属性修正层（ADR-037）

问题：原实现直接改 u.atk / u.maxHp（加完回不去），导致
① 光环无法"条件变化时重算" ② 临时修正在到期后无法回滚。

属性两层结构

最终属性 = 基础属性（卡面值）+ Σ 修正层
             ↑ 固定不变          ↑ 光环 / 临时 buff / 永久 debuff

每个单位持有 mods: StatMod[]，引擎按需重算派生值：

interface StatMod {
  id: string;          // 来源标识（技能 id），重算时按来源整体替换
  kind: 'aura' | 'temp' | 'permanent';
  attack?: number;
  health?: number;
  turns?: number;      // 'temp' 专用：剩余回合
}

光环（aura）

技能声明 kind: aura，其 effects 不立即生效，而是被"收集"成修正项。
收集时完整复用 DSL —— 条件、动态取值、目标选择器全部可用：

- id: hu_wang
  name: 胡王
  kind: aura                      # 光环
  effects:
    - action: modify
      attack_from: { side: both, filter: { tag: man_zu } }   # 每有 1 名蛮族 +1
      health_from: { side: both, filter: { tag: man_zu } }
      target: { source: true }

重算时机（对应 10-skills-statuses.md §4 时机表）：

时机表步骤事件为什么
第 3 步回合开始回合间的状态变化
第 7 步入场后新单位可能改变光环条件
第 19 步死亡后来源阵亡或条件集合缩小
第 21 步清除临时效果后临时修正到期需重算

重算算法：① 清除全部 kind: 'aura' 修正 → ② 遍历双方存活单位的 aura 技能重新收集
→ ③ 按 基础值 + Σ修正 重写 atk / maxHp。

生命修正的处理

生命上限变化时，当前生命等量增减并夹在 [1, 上限]：
获得 +1 上限同时回 1 血；失去 +1 上限则减 1 血，但不会因光环失效而死亡。

约束

项规则
光环内不用 chance每次重算都掷骰会导致数值抖动；需要随机请改用触发技
光环 id 唯一同名光环不叠加，重算时整体替换，避免重复累加
临时修正有 turns到期由时机表第 21 步移除并触发重算

7.8 伤害重定向与免死（ADR-039）

公共逻辑：三国卡的核心互动之一是"替人挨打"。周泰援护、陈宫分担、曹操护驾
三者机制完全相同——伤害本该打在 A 身上，改由 B 承受。做成一个通用机制，
卡面文案各自表述。

伤害重定向

给被保护者施加带 redirect_damage 能力的守护状态，状态记录守护者的 uid；
dealDamage 在扣血前先查这个状态，命中则把伤害整体转给守护者。

- action: apply_status
  status: shou_hu                  # 守护（caps: [redirect_damage]）
  duration: 1
  status_source: self              # ★ 把「来源单位」记为守护者
  target: { side: ally, filter: { type: character }, count: 1, mode: choose }
规则说明
传递顺序伤害整体转移（不是分摊），转移后原目标完全不受影响
守护者阵亡守护者血量 ≤ 0 时守护自动失效，伤害回落到原目标
不自我守护守护者 === 被保护者时忽略，避免自环
递归上限最多转移 3 层，防止 A→B→A 死循环
触发时机时机表第 10 步之前（免疫判定之前），因为"伤害根本没打到原目标"

免死（on_lethal）

单位受到致命伤害时触发一次判定，成功则以 1 血存活。用于周泰、夏侯惇。

- id: bu_si
  name: 不屈
  kind: trigger
  trigger: on_lethal               # ★ 致命伤害时
  chance: 0.5                      # 一半概率（写在技能上）
  effects:
    - action: survive               # 以 1 血存活
规则说明
频率默认 once（一场一次）；数据可声明 frequency
与免疫的区别免疫在扣血前取消伤害；免死在血量归零后抬回 1 血
判定顺序先免疫，再免死

7.9 主公状态 · 费用规则 · 弃牌属性（ADR-040）

① 主公也可承载状态

apply_status 的目标可以是主帅（target: { lord: true }），
主帅状态存放在 Lord.statuses，与单位状态同构（stacks / turns / srcUid）。

用途：断粮（统率上限 −N）、主公技封锁、主公技次数加成。

- action: apply_status
  status: duan_liang
  stacks: 2
  target: { side: enemy, lord: true }
相关能力作用
block_lord_skill该方主帅不能使用主公技（田丰）
extra_lord_skill该方主帅每回合主公技次数 +N（黄权，读取 stacks）

断粮对统率上限的影响在回合开始结算：上限 = min(10, 基础上限 + 1 − Σ断粮层数)。

② 卡牌自身的费用规则 cost_rule

手牌费用除受 mods 影响外，还可由卡牌定义声明一条条件规则（丁奉）：

- id: wu_dingfeng
  cost: 4
  cost_rule:
    condition: { exists: { side: ally, filter: { type: character, health_max: 1 } } }
    value: -1                    # 满足条件时费用 −1

结算顺序：卡面费用 → cost_rule → Σ mods，下限 0。
规则在每次计算费用时重新判定，因此条件变化会自动反映。

③ 读取被弃/被牺牲卡牌的属性

discard 等动作会把被弃的牌记入 ctx.lastDiscarded；后续效果可用
value_from_discarded 取其属性（程昱、华佗）：

- action: discard
  count: 1
  target: { side: self, zone: hand }
- action: heal
  value_from_discarded: cost      # 按被弃牌的统帅值回血
  target: { side: ally, filter: { type: character }, count: 1 }

value_from_discarded 取值：cost | health。

7.10 平衡的基本等式（ADR-043）

这是本作数值设计的第一原则，任何时候都不许只看属性栏。
属性点 + 关键词成本 + 技能价值 ≈ 2 × 费用 + 1

三项互为替代：属性低可以用强技能补，属性高就得砍技能。
所以看到"高费低属性"的卡，先看它的技能值多少分，再判断强弱。

项计价方式
属性点攻击 + 生命，1 点 = 1 分
关键词见 13-§4 的成本表（负值，占用预算）
技能价值按效果折算，见下方 effectValue

工程约定（踩过的坑）

  • DSL 存在 skills[].dsl，不在 skills[].effects。

计价时必须先摊平 skills[].dsl，否则技能价值会被算成 0，
导致所有技能卡都被误判为"严重偏弱"。

  • 新增效果动作时，必须同步在 effectValue 里加估值，

否则该动作按 0 分计，同样会造成误判。
