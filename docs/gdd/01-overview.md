# 01 · 总览与设计支柱

## 1. 一句话定位

> **一款以三国为背景、5 列破阵为核心机制的阵营卡牌对战游戏。**

玩家选择蜀、魏、吴、群雄四阵营之一，以对应主公出战，通过兵种布阵、武将技能、事件与战法卡，击破对方主公。

## 2. 三条设计支柱

### 支柱一：规则极简，卡牌承载深度

- 战场规则只有 **4 条**（见 §4）；
- 所有战术深度来自**卡牌的关键词、技能与羁绊**，而不是规则本身的复杂度；
- 检验标准：新玩家 3 分钟内理解全部规则，30 局后仍在发现新组合。

### 支柱二：内容为王

- 长期留存来自**历史人物卡牌、事件卡、战法卡、羁绊组合**的质量与数量；
- 因此内容必须**数据驱动**：加卡只改数据文件，不改代码；
- 每张卡必须具备"一句话记忆点"（见 `05-cards.md`）。

### 支柱三：破阵斩将的空间感

- 攻击主将需要清空一整列，让"破阵"成为核心战术目标；
- 位置（列/排）是真实决策：近战只能打同列、弓箭手可跨列、盾兵只有在前军才挡人；
- 但位置规则不得超过 4 条，避免认知负荷压过卡牌深度。

## 3. 目标体验

| 项 | 目标 |
|---|---|
| 单局时长 | **6–8 分钟** |
| 回合数 | 10–14 回合 |
| 单局决策密度 | 每回合 3–6 个有效决策 |
| 学习成本 | 3 分钟理解规则，1 局上手，10 局理解兵种克制关系 |
| 情绪曲线 | 前期铺阵 → 中期博弈 → 后期破阵斩杀 |
| 失败归因 | 玩家能说清"我为什么输"（随机性可读，见 `12-randomness.md`） |

## 4. 核心规则一览（4 条）

1. **近战只能攻击同列**：目标列前军为空则打后军，两排皆空则可攻击主将
2. **前空打后（穿透）**：目标列前军为空时，近战可攻击该列后军
3. **全空打主将**：攻击者所在列的两排皆空时，才能攻击敌方主将
4. **架盾最高优先级**：只要场上存在敌方架盾人物，任何普通攻击都必须先打它（可跨列）

## 5. 天时 / 地利 / 人和：随机性与协同的三条轴

这是本作对"随机性"的框架化处理，也是三国题材最自然的表达。

| 轴 | 载体 | 作用 | 玩家感知 |
|---|---|---|---|
| **天时** | 事件卡、随机事件 | 不可控的外部冲击 | "天灾来了，双方都要受损" |
| **地利** | 阵型、位置、列 | 可控的空间决策 | "我守住这条列就赢了" |
| **人和** | 羁绊、阵营、主公技 | 长期构筑与组合 | "刘关张同场才够猛" |

三条轴各自有明确的玩家预期，因此失败原因永远可归因——**这是随机性设计的第一原则**。

## 7. 非目标（明确不做什么）

以下内容**不在 v1 范围**，避免范围膨胀：

- ❌ 单位移动（换位由战法卡提供）
- ❌ 实时 PvP（v1 做 PvE + 异步对战）
- ❌ 第二个资源（只有统率值）
- ❌ 混阵营卡组
- ❌ 装备/武器系统
- ❌ 局内成长（等级/天赋）

## 8. 与工程架构的对应关系

| 设计概念 | 工程实现 |
|---|---|
| 规则 4 条 | `core` 中的攻击合法性判定函数 |
| 关键词（12 个） | `core` 中的关键词注册表，每个关键词一个实现 |
| 状态（12 个） | 状态系统 + 结算时机表驱动 |
| 羁绊 | `bonds.yaml` + 条件求值器，不写代码 |
| 卡牌 | `cards.yaml` + 效果 DSL（见 `13-balance-data-model.md`） |
| 事件/战法 | 与卡牌同一套 DSL，`target: 双方` 表达"天道无情" |
