## 1. 定稿风格

| 维度 | 定稿 |
|---|---|
| 卡面布局 | **立绘铺满**（portrait fills card） |
| 材质主题 | **暗金古典**：**浅底深框**（卡内明亮如插画，卡框深色金属） |
| 卡框装饰 | **无装饰**（金色双层描边 + 内嵌白线 + 暗角） |
| 卡牌尺寸 | **统一 47 × 66 pt**（战场卡 = 手牌卡） |
| 主公 | **位于阵型正前方/正后方**，用横贯的主公条（330 × 24 pt）：头像 + 名 + 生命/护甲 + 主公技按钮 |
| 背景 | **三国古战场叙事场景**（不是纯色/纹理） |
| 卡面文字 | **不放描述文字**（56×78 放不下可读文字）→ 悬浮/点击看详情 |

> **关键修正（2026-09-09）**：卡面从"深色底"改为"浅色底"。
> 实测发现深色卡面时卡牌亮度 0.12、背景 0.23——**卡牌比背景还暗**，视觉上糊成一团。
> 改为浅底深框后，卡牌亮度提升到 0.34，成功从背景中"跳"出来。

## 2. 卡面分层

```
① 立绘层（铺满卡面）：美术图 或 占位（大字 + 阵营渐变 + 纹理）
   · 内嵌双层描边（白线 + 暗线）+ 内暗角 → 像"画框"
② 名称条（顶部，含费用徽章，手牌 9pt）
③ 关键词 chip（紧贴名称条下方）
④ 攻/血宝石（底部左右两角，18pt 圆）
⑤ 金框：4 层 box-shadow（黑描边 / 暗金 / 黑 / 淡金）+ 顶部高光
```

**卡面不放描述文字**——56 × 78 pt 放不下可读的中文，且会与关键词、立绘互相打架。
完整描述放在悬浮/点击的详情面板里。

### 2.1 战场卡 vs 手牌卡

**同一张卡、同一尺寸**，唯一区别是战场卡不显示费用宝石、阵营纹章与描述文字（空间留给立绘）。

| 元素 | 手牌卡 | 战场卡 |
|---|---|---|
| 立绘 | ✅ | ✅ |
| 名称 | ✅ | ✅ |
| 关键词 | ✅ | ✅ |
| 攻/血 | ✅ | ✅ |
| 费用 / 纹章 / 描述 | ✅ | ❌ |

## 3. 尺寸与布局

### 3.1 统一 47 × 66 pt

| 卡类 | 尺寸 |
|---|---|
| 战场单位 | 47 × 66 |
| 手牌 | 47 × 66 |
| 主公 | 330 × 24（横条，不占格） |

> **尺寸取舍（2026-09-09）**：要让"空列直击主将"在视觉上成立，主公必须位于阵型正前方/正后方。
> 纵向预算为 `4×卡高 + 2×主公条 + 手牌区 + 间距 ≤ 414`，
> 因此卡牌从 56×78 降到 **47×66**（约 84%）。这是几何硬约束，不是随意缩小。

### 3.2 战场布局（736 × 414 画布）

```
┌────────────────────────────────────────────────────────┐
│                     三国古战场背景                       │
│  ┌──────┐   ┌────┬────┬────┬────┬────┐   ┌──────────┐  │
│  │敌主公│   │        敌方后军         │   │ 统率值    │  │
│  ├──────┤   ├────┬────┬────┬────┬────┤   │ 回合/牌库 │  │
│  │我主公│   │        敌方前军         │   │ 结束回合  │  │
│  └──────┘   │═══ 中线 ═══            │   └──────────┘  │
│             │        我方前军         │                 │
│             │        我方后军         │                 │
│             └────┴────┴────┴────┴────┘                 │
├────────────────────────────────────────────────────────┤
│                    手牌区（56 × 78）                    │
└────────────────────────────────────────────────────────┘
```

**为什么主公在侧边而不是上下**：4 行卡（78×4=312）+ 手牌行（78）已经占满 414pt 高度，放不下主公条。
主公改为侧边卡后，纵向全部留给战场与手牌，且主公以卡牌形式呈现更符合"卡牌游戏"的直觉。

| 区域 | 尺寸 |
|---|---|
| 战场宽 | 5 × 56 + 4 × 6 = **304 pt** |
| 两侧余量 | 各约 115 pt（背景场景 + 侧栏） |
| 手牌区 | 80 pt |

## 5. 立绘规范

| 项 | 规范 |
|---|---|
| 路径 | `art/<card_id>.png`（例：`art/shu_guanyu.png`） |
| 建议尺寸 | 512 × 512 |
| 构图 | 人物居中，**头部位于上 1/3** |
| 背景 | 透明或纯色（卡面已有阵营渐变底） |
| 接入 | 卡牌数据加 `art: "art/shu_guanyu.png"`，**无需改代码** |
| 裁切 | `object-fit: cover` + `object-position: 50% 22%`（优先露脸） |

### 5.1 占位方案（美术未到位时）

- 大字：卡名首字，衬线字体，白色 17% + 阵营色外发光；
- 底色：阵营径向渐变；
- 纹理：斜向细线（角度按 id 哈希）；
- **色相偏移 ±22°**：同阵营的卡也互不相同。

> **交付前必做**：把立绘缩到 56 × 78px 看一眼——认不出是谁，这张图在战场上就是失败的。

## 6. 战场背景规范

### 6.1 设计目标

> **背景要讲一个故事，不是一块布。**

参照炉石：每个对战板都是一个场景。本作是三国，所以背景必须是**中国古代战场**。

### 6.2 必须包含的元素（分层）

| 层 | 内容 | 说明 |
|---|---|---|
| 1 | 天空 | 黄昏/黎明渐变（暗紫 → 赭红 → 墨） |
| 2 | 日 / 月 | 低垂的光源 + 光晕 |
| 3 | 云 | 横贯的暖色云带 |
| 4 | 远山 | 淡色剪影，2 层，制造纵深 |
| 5 | 城墙 / 烽火台 | 中景剪影 |
| 6 | 旗帜 | 朱红战旗，风吹姿态 |
| 7 | 地面雾 | 底部雾气，让卡牌区浮起来 |
| 8 | 暗角 | 四角压暗，聚焦中央 |

### 6.3 留白要求（给美术）

| 项 | 要求 |
|---|---|
| 画布 | 736 × 414（横屏） |
| **中央禁区** | 约 560 × 330 的"桌面区"**不要放重要元素**（会盖住卡牌） |
| 亮度 | 中央区域整体压暗，保证卡牌对比度 |
| 配色 | 与暗金卡框互补：暖橙 / 赭红 / 墨青 |
| 风格 | 写实或半写实，避免卡通 |

### 6.4 接入方式

```css
#bg-scene.has-image {
  background-image: var(--bg-image);   /* 换成美术图 */
  background-size: cover;
}
```

原型里已用纯 CSS 画了一个占位场景（天空 / 落日 / 远山 / 城墙 / 烽火台 / 战旗 / 雾 / 暗角，共 16 层），
**仅用于验证氛围与遮挡关系**，正式版必须替换为绘制插画。

## 7. 动画清单

| 动画 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| **出牌飞行** | 380ms | `cubic-bezier(.22,.85,.3,1)` | 手牌卡飞向目标格（**同尺寸，无缩放**） |
| 落地闪光 | 420ms | `ease-out` | 径向白光扩散并淡出 |
| 落地回弹 | 300ms | `ease-out` | 1.18 → 0.96 → 1 |
| **攻击冲刺** | 340ms | `ease-in-out` | 攻击者向目标移动 60% 距离，放大 1.08 |
| 受击抖动 | 300ms | `ease-out` | 位移 ±3px，衰减 |
| 伤害数字 | 700ms | `ease-out` | 上浮 34px + 淡出 |
| **死亡** | 380ms | `ease-in` | 缩小 0.72 + 旋转 −7° + 淡出 |
| 抽牌 | 320ms | `ease-out` | 从下方滑入并放大 |
| 关键词触发 | 500ms | `ease-out` | 图标光环扩散 9px |

> 由于战场卡与手牌卡同尺寸，出牌动画**不再需要缩放**——视觉上就是"同一张卡从手牌移动到战场"，这是统一尺寸带来的直接好处。

## 8.3 破阵的可视化（关键规则的可读性）

规则"攻击者所在列两排皆空 → 可攻击敌方主将"必须在界面上**一眼看懂**，靠三点：

| 手段 | 实现 |
|---|---|
| **主公位于阵型正前方/正后方** | 主公条横贯整个阵型宽度（330pt），任何一列都"指向"它 |
| **空列通道光束** | 敌方某列两排皆空 → 该列浮现金色光束 + 向下箭头，脉动提示 |
| **主公条高亮** | 选中该列单位时，若可直击主将，主公条亮绿框 |

> 架盾存在时，光束仍在但主将条不高亮——因为"必须先破盾"优先级更高。
> 视觉与规则完全一致。

## 8.4 战场布局红线（踩过的坑）

| 规则 | 原因 |
|---|---|
| **战场容器禁止用 `perspective` / `rotateX`** | 透视会让每一行的缩放不同（实测四行宽度 402/404/407/409px），**网格无法对齐**。纵深靠光影（远端行压暗）而不是变形。 |
| 空格子不画虚线框 | 虚线框让战场像线框稿。改为桌面上的**凹槽**（内阴影 + 微弱高光）。 |
| 主公不做成卡牌 | 卡牌样式的主公与场上人物混淆；改拱形人物头像框后辨识度明显提升。 |

**对齐自检**：四行的格子 x 坐标必须完全一致。
```js
// 期望四行输出相同的 left/width 序列
document.querySelectorAll('.row').forEach(r =>
  console.log([...r.querySelectorAll('.slot')].map(s => s.getBoundingClientRect().left)));
```

## 8.5 视觉迭代方法（重要）

**不要盲改 CSS。** 本项目的视觉迭代流程：

```bash
# 1. 改 CSS / 结构
# 2. 截图（1:1 与常见视口各一张）
./prototype/shot.sh battlefield 736 414
./prototype/shot.sh battlefield 1200 700
# 3. 用 read_image 看图，再决定下一步
# 4. 必要时量化对比：卡牌亮度 vs 背景亮度
python3 tools/see.py .screenshots/battlefield-736x414-clean.png
```

**量化红线**（来自实测经验）：

| 指标 | 目标 | 说明 |
|---|---|---|
| 卡牌平均亮度 | ≥ 0.30 | 低于 0.2 会糊进背景 |
| 背景平均亮度 | ≤ 0.20 | 背景要比卡牌暗 |
| 卡牌 − 背景 | **≥ +0.12** | 小于 +0.05 时视觉上"卡牌没有存在感" |
