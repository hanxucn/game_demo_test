# 03 · 对局流程与回合结构

> 状态：**已定**（开局流程已实现于 `core/src/setup.ts`，见 ADR-044）

## 1. 对局建立流程

```
① 双方选择阵营（蜀 / 魏 / 吴 / 群雄）
      ↓ 自动任命主公（刘备 / 曹操 / 孙权 / 董卓）
② 双方换牌（起手可替换任意张数，每张仅一次机会）
      ↓
③ 掷点决定先手（系统随机，不比较卡牌统率）
      ↓ 后手额外获得「传国玉玺」
④ 先手方开始第 1 回合
```

> **已移除：原第②步「双方各选一个酒令」**。设计者确认酒令非其设计（见 ADR-048），
> 整套机制已撤除。原「酒令」章节在 `11-events-tactics-jiuling.md` §3 保留存档。
>
> **已裁定**（ADR-053）：「掷点决定先手」保留；原「后手补传国玉玺」**已删除**
> （设计者确认非其设计，源自初始提交的 GDD 草案），后手补偿改为**后手第 1 回合多抽 1 张**。

**实现对应**（`core/src/setup.ts` / `core/src/state.ts`）：

| 步骤 | 函数 | 说明 |
|---|---|---|
| ① 选阵营 / 任命主公 | `autoDeck` + `loadData` | 主公由 `data/heroes.yaml` 按阵营固定 |
| ② 换牌 | `mulligan` | 任意张数、每方一次、换 N 补 N |
| ③ 掷点定先手 | `rollFirstSide` | D6 平局重掷；后手补偿由 `createMatch` 的 `secondCompensation` 决定 |
| ④ 开打 | `startMatch` → `applyAction` | 唯一写入口 |

> `createMatch` 是**纯构造器**：缺省先手为 `own`，只有显式传 `rollFirst: true` 才掷点。
> 完整开局编排用 `setupMatch()`（不传 `firstSide` 即自动掷点）。

### 1.1 为什么先手用掷点而不是"比统率"

- 早期方案（各抽一张比统率）会**泄露牌库信息**，且引入不必要的前置随机；
- 掷点简单、可读、无信息泄露；
- 后手补偿用「第 1 回合多抽 1 张」补足节奏差（原「传国玉玺」已删，ADR-053）。

### 1.2 起手与补偿

| 项 | 先手 | 后手 |
|---|---|---|
| 起手牌 | 3 张 | 4 张 |
| 额外 | — | 第 1 回合多抽 1 张 |
| 第 1 回合统率 | 1 | 1 |

**后手补偿**：后手方在自己第 1 个回合的抽牌阶段**多抽 1 张**（即该回合抽 2 张）。

## 2. 回合结构

回合分为三个阶段，顺序固定：

```
┌─────────────────────────────────────────────┐
│ ① 回合开始阶段                                │
│   1. 统率值上限 +1（最高 10），统率值恢复至上限   │
│   2. 抽 1 张牌（牌库空 → 触发粮尽，见 §4）      │
│   3. 结算「回合开始」类效果：                    │
│      · 顺序：己方人物卡从左到右、先前军后后军     │
│      · 例：急救回血、陷阵营回血、光环生效、中毒结算 │
├─────────────────────────────────────────────┤
│ ② 行动阶段（自由顺序，无次数限制除下述）          │
│   · 使用卡牌（消耗统率值）                       │
│   · 发起普通攻击（每张人物卡每回合 1 次）          │
│   · 使用主将主动技（每回合 1 次）                 │
│   · 使用酒令效果（按酒令定义）                    │
│   · 顺序完全自由：可先攻击再出牌，也可穿插         │
├─────────────────────────────────────────────┤
│ ③ 回合结束阶段                                 │
│   1. 结算「回合结束」类效果（例：中毒、灼烧）       │
│   2. 清除「本回合」临时效果（例：本回合 +2 攻）     │
│   3. 手牌上限检查：超过 10 张则弃牌至 10 张        │
│   4. 交出行动权给对手                           │
└─────────────────────────────────────────────┘
```

### 2.1 为什么不分"出牌阶段 / 战斗阶段"

- 与炉石一致的自由顺序，学习成本最低；
- 卡牌游戏的核心乐趣之一是"先攻击再出牌还是先出牌再攻击"的顺序决策；
- 阶段划分会把这个决策空间砍掉。

### 2.2 结算顺序的重要性

当多个效果同时触发时，顺序会决定结果（例如"回合开始回血"与"回合开始掉血"的先后）。
完整规则见 `10-skills-statuses.md` §结算时机表。

## 3. 胜负判定

| 条件 | 结果 |
|---|---|
| 敌方主将生命 ≤ 0 | 己方胜利 |
| 己方主将生命 ≤ 0 | 己方失败 |
| 双方主将同时归零 | **平局** |
| 一方投降 | 对方胜利 |
| 回合数达到上限（默认 40 回合） | 主将生命值高者胜；相同则平局 |
| 一方连续超时（默认 2 次，每次 60 秒） | 该方判负 |

> 护甲在生命之前被扣除，因此"护甲未破"时不会因伤害导致失败。

## 4. 粮尽（牌库耗尽）

| 项 | 规则 |
|---|---|
| 触发 | 回合开始阶段抽牌时，牌库为空 |
| 伤害 | 第 1 次 1 点，之后每次递增 1 点（1、2、3…） |
| 目标 | 抽牌方的主将（先扣护甲） |
| 计数 | 每方独立累计，不重置 |
| 设计意图 | 防止无限拖延，给"控制流"对局一个自然终点 |

## 5. 时间与超时

| 项 | 规则 |
|---|---|
| 每回合时限 | 60 秒（可配置） |
| 超时处理 | 自动结束当前回合，交出行动权 |
| 连续超时 | 2 次判负 |
| 断线重连 | 60 秒内可恢复；超时视为投降 |

> 时限与重连策略在 v1 的 PvE 场景下不启用，仅用于后续 PvP。

## 6. 对局参数速查

| 参数 | 值 |
|---|---|
| 主公生命 | 30 |
| 统率值 | 1 → 10 |
| 卡组 | 30 张 |
| 起手 | 先手 3 / 后手 4（+ 第 1 回合多抽 1 张） |
| 换牌 | 一次，任意张数 |
| 手牌上限 | 10 |
| 每回合抽牌 | 1 |
| 回合上限 | 40 |
| 目标时长 | 6–8 分钟 / 10–14 回合 |
