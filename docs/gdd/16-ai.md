# 对战 AI

> 状态：已实现（ADR-084）· 代码：`core/src/ai/` · 报表：`cd core && npm run ai:report`

本文是 PvE 对手 AI 的机制真源。设计目标一句话：

> **像一个懂这套牌的对手那样下棋** —— 会算换牌亏不亏、会挑技能目标、会按自己的牌组风格决定打脸还是解场。

AI 只做**决策**，不做结算。所有结果都由 `core` 的 `applyAction` 产生 ——
这是「双方技能平等生效」的结构性保证（见 §6）。

---

## 1. 三层架构

```
core/src/ai/
  cards.ts     卡牌理解    一张卡值多少、这个效果想干什么
  profile.ts   卡组画像    这副牌是速攻 / 中速 / 后期 → 三档评估权重
  eval.ts      局面评估    给一个局面打分（唯一的"棋感"来源）
  options.ts   候选生成    当前局面下引擎会接受的全部动作
  index.ts     搜索决策    把每个候选交给引擎跑一遍，取打分最高的
```

### 1.1 决策流程（`index.ts`）

```
① 画像     profileFor(state, side)              → 权重
② 基线     evaluate(state, side, w)             → "什么都不做"的分
③ 候选     generateOptions(state, ctx, w)       → 全部合法动作（按 quick 预排序）
④ 模拟     对每个候选 applyAction(state, ctx, a) → 得到真实结算后的局面
⑤ 打分     evaluate(新局面, side, w)
⑥ 决策     最高分 > 基线 → 执行；否则返回 null（调用方结束回合）
```

两条硬约束：

* **斩杀优先**：任何候选让 `state.winner === side` 就立刻执行，不再看别的。
* **严格单调**：只有比基线更好的动作才会被执行 → 同一回合里分数只增不减，
  不可能出现"两个动作来回横跳"的死循环（旧 AI 曾把对局卡在第 10 回合 4000 步）。

`SIM_BUDGET = 160`：单步最多模拟 160 个候选。实测一次 `applyAction` 约 0.05–0.15ms，
即单步 10–20ms —— 相对于原型 320ms 一步的动画节奏完全无感。

### 1.2 为什么用「模拟」而不是「自己写一套战斗结算」

反击、圣盾、饮血、亡语、攻击时触发技、光环重算、免死、伤害重定向……
这些规则在 `effects.ts` 里已经各有一份实现，而且**天天在改**。
AI 若自己再写一份"预计伤害 = 攻击力 − 目标血量"，必然与引擎漂移，
表现为「AI 以为能白吃、结果自己被反杀」。

交给 `applyAction` 之后，AI 看到的后果与玩家打出来的**逐字节相同**，
以后加新机制（护甲穿透、连击、新的触发时机）**不需要动 AI 一行**。

## 2. 局面评估（`eval.ts`）

以「**1 点场面战力当量 = 1.0**」为锚，七项相加：

| # | 分项 | 说明 | 对应设计者要求 |
|---|---|---|---|
| ① | 主将有效血量 | 血量 + 护甲之差 × `face`，并乘**收尾系数**（对手 ≤20 血时线性放大，逼近 0 血翻倍） | ⑤ 最终目标是击杀主公 |
| ② | 场面战力 | Σ 己方单位当量 − Σ 敌方单位当量，× `board` | ①②③ 换牌收益 |
| ③ | 人数差 | 单位数量之差 × `width`（以多打少的优势） | ⑥ 铺场运营 |
| ④ | 手牌 | Σ 手牌价值 × `hand`（卡差） | ⑥ 后期运营 |
| ⑤ | 未用统率 | `command.cur` × `mana`（统率每回合清零，不用就是白扔） | 通用 |
| ⑤′ | **未用的攻击机会** | 本回合还能攻击的单位攻击力之和 × `ready`（只算当前行动方） | 攻击分配的平局裁决 |
| ⑥ | 被斩风险 | 对手**场攻**覆盖我血线时重罚（只算场上，不偷看手牌） | 通用 |
| ⑦ | 粮尽 | 牌库见底方的递增伤害 | 通用 |

### 2.1 单位战力当量（`unitValueOf`）

```
当量 = (攻击 + 当前生命) + 关键词价值 + (卡牌预算 − 卡面属性点 − 关键词) × 0.6 + 卡牌价值
                                          └── 技能预算残差              └── cardEquityOf
卡牌预算 = 2 × 费用 + 1        （GDD 13 的基本等式）
```

四个要点：

* **用预算而不是卡面数值**估价 —— 才不会把「低属性强技能」的高费卡（公孙瓒、袁绍）当成废牌。
* **关键词只计已实现的**（架盾 / 圣盾 / 连击 / 先攻 / 遗计 / 饮血）；
  神射 / 奇袭 / 忠义在引擎里还是白板，计进去会让 AI 高估一批实际没效果的卡。
* **当前生命参与计算** —— 磨掉 3 点血就是实打实削弱了它的战力，AI 因此会"磨大怪"。
* **卡牌价值（卡差）**：能进卡组的类型 +2.0，进不了卡组的（衍生物 / 精英 / 状态 / 特殊）+0。
  判据复用 `NON_DECK_TYPES`，与组卡规则同一个真源，**不写死卡名**。

### 2.2 攻击分配：谁去解场、谁去打脸

设计者实机要求：*「AI 攻击要算最优攻击 —— 3/3 与 4/5 面对对方 2/2，应该 3/3 解掉 2/2、4/5 去打主将，
这样主公受到的伤害更高；如果面对的是 3/2，则应该 4/5 去解，这样两张人物卡都存活。」*

两种情况性质不同：

* **打 3/2 那种**（谁去结果不同）——评估天然算得对：3/3 去会同归于尽（丢 8 点当量），
  4/5 去能剩 4/2 活着（只丢 3 点），**Agent 直接选后者**，不需要额外机制。
* **打 2/2 那种**（谁去都一样）——**单纯按血量算两边完全同分**，旧版只能按格子顺序瞎选：
  4/5 恰好站在左边时就会由它去解场，主将只吃 3 点而不是 4 点。
  修法是 `ready` 项：**没行动的攻击力是一种会过期作废的资源**，计入评分后，
  AI 会把解场交给"刚好够用"的那个，把大攻留给主将。

`ready` 的取值必须**严格小于 `face`**（本项目取 `0.5 × face`）：
否则 AI 会为了"留着攻击机会"而不敢打脸，变成一味空过。
回归测试用**两个站位各跑一遍**，断言结论不跟着列号走。

> **卡牌价值这一项是设计者实机截图逼出来的**（ADR-084 ⑦）：马腾战吼召唤的两个 2/1 先攻「西凉铁骑」
> 面对 2/2 蔡瑁，AI 全部打脸。按「攻+血」算 3 换 4.6 只赚 1.6，还不如 2 点打脸（0.9 → 1.4 带权重）。
> 但真实收益是**对手拿牌库里的牌换掉我一个白送的衍生物** —— 纯卡差。
> 补上卡牌价值后同一局面：衍生物换 2/2 = 11.3 分，打脸 = 9.5 分，AI 改为解场。
> 判据落在 `NON_DECK_TYPES` 上，意味着以后新增召唤物类型只要类型登记正确，
> 不用回来改 AI。

### 2.2 打脸 vs 解场的换算

主将 30 血、单位 4–8 点当量、一局 8–15 个完整回合 ——
所以 1 点打脸 ≈ 1/30 的胜势，而清掉一个 2 费人物 ≈ 5 点当量（还含它之后的持续输出）。
数值上「能白吃就解场」本来就该赢过糊脸，这就是第 1 条策略的实现方式，
不需要额外写一条 `if (能击杀) 去击杀`。

## 3. 卡组风格画像（`profile.ts`）

用户要求的两条相反策略（速攻少解牌多打脸 / 后期多站场）不可能用一套权重同时满足，
所以先给**卡组**定风格，再据此调权重。

**取样口径 = 整副牌**：牌库 + 手牌 + 弃牌堆 + 场上单位还原成开局那 30 张。
只看「牌库里剩下的牌」会让画像随对局漂移 —— 打着打着从快攻变成控制。

判档只看曲线（不看单张强卡）：

| 档位 | 条件 | face | board | width | hand | threat |
|---|---|---|---|---|---|---|
| 速攻 aggro | 均费 ≤ 2.5 或 1–2 费占比 ≥ 50% | 0.70 | 0.85 | 0.30 | 0.40 | 0.50 |
| 中速 midrange | 其余 | 0.45 | 1.00 | 0.50 | 0.55 | 0.90 |
| 后期 control | 均费 ≥ 3.6 或 5 费以上占比 ≥ 32% | 0.32 | 1.15 | 0.70 | 0.75 | 1.20 |

`mana` 一律 0.06、`fatigue` 0.8–1.0。

**调参原则**：只调这三档，不做连续插值 —— 插值看着精细，但没法用测试固定行为，
出了问题也说不清是哪一档偏了。任何一档改动都必须让 `core/test/ai.test.ts` 里
对应的行为断言（速攻打脸 / 后期换牌）仍然通过。

## 4. 候选生成（`options.ts`）

**合法性一律取自引擎**，AI 不自己判断"这个目标合不合法"：

| 候选 | 合法性来源 |
|---|---|
| 攻击 | `canAttack` + `legalTargets` |
| 出牌（含费用） | `canPlayCard` + `effectiveCost` + `costRuleDelta` |
| 人物主动技 | `canUseUnitSkill` |
| 主公技 | `canUseLordSkill` |
| 指向性选择 | `playTargetPlan` / `unitSkillTargetPlan` / `lordSkillTargetPlan` |

后三个 plan 函数**同时供原型 UI 使用**（ADR-077）。AI 与玩家看到的是同一份目标集，
不可能出现"玩家点得到的合法目标，AI 选不到"。

### 4.1 展开的维度

* **抉择分支**：`modes` 的每一支都按自己的选择器重新取 plan（曹彰「猛袭」两支的目标集不同）。
* **指向性目标**：按启发式排序后取前 4 个（第二个选择取前 3），排序依据来自
  `PlayTargetChoice.action` —— `damage/destroy` 选敌人、`heal/modify` 选自己人、
  `modes` 里 `side: 'both'` 的（仁德、程昱）靠动作语义而不是 label 判方向。
* **手牌选择**：引擎读 `ctx.handIndex`，**缺省是随机**（对玩家等于"系统替我乱扔牌"）。
  AI 列出最贵 / 最便宜 / 中间三张交给模拟决定 —— 华佗青囊的治疗量 = 弃牌统率，
  扔贵牌治得多、扔便宜牌亏得少，这是真取舍，不该由 AI 预设。
* **落点**：只有带 `adjacent_to` 的效果才逐格比较，其余位置等价（单排、无列位机制）。

### 4.2 预排序（`quick`）

只用于决定"谁先进模拟预算"，不参与最终决策：
能斩杀的必定置顶（`1e6`），其次按「白吃 > 同归于尽 > 换不掉」粗排，
出牌按卡牌预算，技能给个小常数。

## 5. 换牌（`aiMulligan`）

判据只有一条：**这张牌我第一个回合能不能用**。

* 3 费及以下留下；
* 速攻牌组把 4 费以上全换掉，中后期牌组容忍到 5 费；
* 若整手都是贵的，只换最贵的两张（全换等于把"高费炸弹"也扔了）。

---

## 6. 双方平等（设计者第 7 条）

技能平等**不靠 AI 自觉**，靠三件事保证：

1. **同一个写入口**：AI 与玩家都只通过 `applyAction` 改变状态，
   触发技、亡语、光环在 `effects.ts` 里按 `side` 遍历双方，没有任何 `side === 'own'` 的分支。
2. **同一份判定**：`canAttack` / `canUseUnitSkill` / `canUseLordSkill` / `legalTargets` /
   三个 `*TargetPlan` 都是引擎与 AI 共用。**AI 不许另抄一份** ——
   ADR-084 修掉的正是这样一处漂移（AI 自己抄的主公技门控漏了「进言」，每回合提一次必被拒）。
3. **同一条模拟链路**：AI 判断"打了会怎样"用的就是引擎的结算函数。

回归测试 `core/test/ai.test.ts` 里锁了两条：
* 「敌方 AI 一样会释放主动技」（受控局面断言敌方 `USE_SKILL` 与目标）；
* 「候选动作 100% 引擎合法」（跑真实卡池三个阵营，逐个候选交给引擎验证）。

## 7. 验收与实测

```bash
cd core
npm test                      # 含 test/ai.test.ts：每条策略一个受控局面断言
npm run ai:report             # 20 局统计：胜率 / 攻击构成 / 技能使用 / 决策耗时
npm run ai:report -- --games 40 --own wei --enemy shu --verbose
```

| 指标 | 数值 | 对照 |
|---|---|---|
| 攻击打人物 : 打主将 | **43% : 57%** | 旧 AI 是 10% : 90%（ADR-052） |

| 动作被引擎拒绝 | **0** | 旧 AI 偶发 |

## 8. 已知边界（不要当成缺陷）

* **只有 1 层搜索**：能算清"我这一手打出去的后果"，算不到"对手下回合怎么还手"。
  缓解手段是评估里的「被斩风险」项（用对手场攻估算）。要做 2 层搜索得先解决分支爆炸，
  当前收益不足以支撑。
* **不偷看手牌**：对手手牌里的直伤不计入被斩风险 —— 这是**刻意**的，AI 不该有全知视角。
* **落点等价**：单排 8 格、无列位机制，落点只在 `adjacent_to` 类效果下参与比较。
* **风格只分三档**：更细的风格识别需要先有真实卡组构筑数据。
