**判别式**：`属性点 + 关键词成本 + 技能价值 ≈ 2 × 费用 + 1`（三项互为替代，属性低 ≠ 卡弱）

**执行摘要**：16 张里 **13 张建议改**、**3 张（高顺 / 马腾 / 张角）建议不动**。
最大发现不是任何一张卡，而是 `effectValue()` 的 **`transform` 定价漏算属性差**，
以及 **`damage` 忽略 `count`**——先修度量，再动数值，否则会照着错误分数砍掉对的卡。

## §2 系统性偏差（最高价值部分）

16 张按根因归为 **5 组**，其中 3 组只需**改一处**即可批量消除：

### A. `transform` 漏算属性差 → 3 张（高顺 / 公孙瓒 / 马腾，合计 +15.0）
三张卡结构完全相同（4 费 2/2、`summon count=2` + `transform count:all`），
但 `baseEffectValue` 把 `transform` 写成 **固定 4 分**（`case 'transform': return 4`），既不读进化前后的属性差，也不读受影响单位数。

| 卡 | 进化前后 | 每只属性差 ×1.5 | 关键词差 ×1.0 | 2 只合计 | 指标记分 | 差额 |
|---|---|---|---|---|---|---|
| 高顺 | 盾兵 1/2 → 陷阵盾兵 2/2 | +1 攻 = 1.5 | 架盾保留 = 0 | **3.0** | 4.0 | 高估 1.0 |
| 马腾 | 步兵 1/1 → 西凉铁骑 2/1 | +1 攻 = 1.5 | 先攻 = 1.0 | **5.0** | 4.0 | 低估 1.0 |
| 公孙瓒 | 弓射手 0/1 → 白马义从 1/2 | +1 攻 +1 血 = 3.0 | 神射→每回合 2 伤 ≈ +1.0 | **8.0** | 4.0 | **低估 4.0** |

三张的进化**收益差近 3 倍**，却被记成同一个 4.0——固定值必然是错的。
**一处修**：`transform` 改为 `(Σ进化后属性 − Σ进化前属性) × 1.5 + Σ关键词差 × 1.0`（乘受影响单位数）。
修完：高顺 13.0（仍 +4.0，需再收）、马腾 15.0（实际偏强，不能因为"指标转正"就放过）、
公孙瓒 **18.0**（指标说 +5.0、真相是 +9.0，**方向都反了，必须削卡**）。

### B. 代价类动作被记成正收益 → 4 张（马谡 / 程昱 / 周瑜，含 `discard`）+ 1 张（华雄，重复计价）
- `discard` 一律 **+1.5/张**：弃**自己**的牌（马谡 `count=2`→+3.0、程昱 `count=1`→+1.5）是**代价**，应记 0；
  弃**对手**的牌（周瑜）才有效益，且强度只有抽牌的 1/3，建议 **1.0/张**，且要区分 `target.side`。
- `shu_masu` 的"抽2弃2"净手牌变化为 **0**，却被算成 **+9.0**，是单卡最大的假溢价。
- `qun_huaxiong` 的两条震慑 filter 互斥（`cost_below_source: true` vs `cost_max: 3`），
  **引擎两条都结算**等于同一机制写两遍；这不是定价问题而是**数据表达问题**，应合并成一条。

### C. `damage` / `apply_status` 忽略重复与规模 → 3 张（张角 / 陆逊 / 司马懿）
`damage` 只读 `value`，不读 `count`（张角 `count=5` 白丢）；也不读 `target.count: all`
（陆逊、司马懿的全体回合末伤害按单体 0.5 计）。全卡池共有 **14 张**卡使用 `target.count: all`
（含关羽水淹七军、张飞咆哮、贾诩离间毒计、甘宁百骑劫营），受影响的远不止这 3 张。

### D. 高费卡的效果天然"不可静态定价" → 结构性偏弱（12/16）
全卡池 87 张人物卡中，**≥5 费有 12 张偏弱、只有 4 张偏强；≤4 费有 19 张偏弱、11 张偏强**——
偏差的**符号与费用正相关**，说明问题不在单卡，而在"高费卡承载的效果类型"。
≥5 费偏弱的 12 张 = 9 张谋臣 + 3 张武将：
`黄月英 / 诸葛亮 / 程昱 / 荀彧 / 郭嘉 / 司马懿 / 陆逊 / 周瑜 / 张角`（谋臣）
+ `黄忠 / 张飞 / 姜维`（武将）。
它们的效果属于**手牌操控、牌库操控、重复触发、多目标、条件触发**——
全部是"每回合都会再赚一次"的引擎，而 `effectValue` 给的是**一次性买断价**。
**建议一个源头修**：给"回合结束/回合开始触发的持续性引擎"加**回合数乘子**（建议默认 **2.5 回合**存活期望），
或对 `turn_end`/`turn_start` 触发不重复打 0.7 折扣（0.7 折扣已经隐含了存活率，再乘"只算一次"就是双重折价）。

### E. 效果写在卡级而非技能级 + 缺失 effect → 3 张（马谡 / 郭嘉 / 司马懿）
`data/cards.yaml` 里 `shu_masu` 的效果在卡级 `effects:`，`skills[0]` 的 `effects` 为空、
`text` 是占位（"抽取两张…"这种描述也没写进 `text`）；
`wei_simayi` 的文案 ②③ 与 `qun_zuoci` 的"死亡回牌库"**没有 effect**，属实现遗漏而非平衡问题。
**建议**：在 `validate.ts` 加一条数据检查——`skills[].text` 非空但 `skills[].effects`（或 `dsl`）为空时报错，
可一次性堵住这类"技能分算成 0"的坑（与刚刚修掉的 `skills[].dsl` bug 同源）。

## §3 度量本身的疑似缺陷（`core/tools/validate.ts` `effectValue()`）

| # | 动作 | 现状 | 疑似正确价 | 暴露此缺陷的卡 | 置信 |
|---|---|---|---|---|---|
| ① | `damage` / `apply_status` | 忽略 `eff.count`；忽略 `target.count: all` | `damage` 总伤 = `value × count`；`target.count: all` 按 **3 目标**（5 列 2 排的典型在场数）计 | `qun_zhangjiao`（count=5 记 0.5）、`wu_luxun`、`wei_simayi`、关羽 / 张飞 / 贾诩 / 甘宁 | **高**（`count` 漏读是 bug，不是判断） |
| ② | `survive` | **固定 6**，且 `skills[].chance` 不参与折扣（`skillValue` 把 `chance 0.5` 的"血战""不屈"按 6 分算） | **3.5**。依据：免死只把一次死亡延后一回合，不解决任何场面问题；且它需要"被击杀"这个前提，实际期望收益 ≈ 一次 1 血站场。当前价高于"销毁(8)"所隐含的强度曲线 | `wu_zhoutai`（4.8/6.2 = 77%）、`wei_xiahoudun`（4.8/5.7 = 84%） | 中（单价 3–4 都可辩护，但 6 明显偏高） |
| ③ | `discard` | 一律 **+1.5/张**，不区分弃谁的牌 | 弃**自己** = **0**（是代价，与 `cost` 同性质）；弃**对手手牌** = **1.0/张**（抽 1 张 = 3 分，让对方少 1 张 ≈ 其 1/3） | `shu_masu`（抽2弃2 被记 +9.0）、`wei_chengyu`、`wu_zhouyu` | 中高（"代价记收益"是明确错误；对手弃牌单价待校准） |
| ④ | `transform` | **固定 4**，不读属性差、不读 `count`/`target.count` | `(进化后属性 − 进化前属性) × 1.5`，再乘受影响单位数，另加关键词差（先攻 −1、架盾 −1）。参考 `修改属性 ×1.5/点` 与 `关键词价值表` 自洽 | `qun_gaoshun`（真值 3.0 记 4.0）、`qun_mateng`（真值 5.0 记 4.0）、`qun_gongsunzan`（真值 8.0 记 4.0） | 高（三张卡结构相同、真值差近 3 倍，说明固定值一定错） |
| ⑤ | `ban_play` | (count 1) **2.5** | **4.5–6**。`apply_status zhen_she` 对**场上单位**锁一回合记 5，而 `ban_play` 锁的是**对手手上更贵的一张**、且对手无法用解场手段救，强度不低于震慑 | `shu_zhugeliang`（ban_play+scry 合计仅 4.0，撑不起 7 费） | 中（区间宽，需实测对手手牌被锁的价值） |
| ⑥ | `value_from_discarded` | **未定价 = 0** | `heal ×0.4 × 预估值 3`、`damage ×0.5 × 预估值 3`，并因需先弃牌再乘 `CONDITION_RATE 0.7` | `wei_chengyu`（卡牌核心机制，被记 0 分） | 中高（记 0 必错，数值待校准） |
| ⑦ | 持续光环 / 引擎 | 一次性买断价（`cost_modifier` 每点 2 分、`draw` 每张 3 分） | 建议引入**回合数乘子**或取消 `turn_end`/`turn_start` 的 0.7 折扣（0.7 已含存活率，再乘一次即双重折价） | `wei_guojia`、`wei_simayi`、`wu_luxun`、`shu_zhugeliang` | 低（方向明确，系数必须用模拟器回归，见 T-13-2） |
| ⑧ | 预算公式本身（低置信，仅作待验证项，**本次不据此改动任何卡**） | `2 × cost + 1` 线性 | 当前数据下 **≥5 费普遍 −3～−7、≤4 费普遍 0～+5**，与"线性公式在高费区高估了费用"的形态一致。**但样本也可解释为"高费卡恰好都是复杂效果"**，两者无法用静态数据区分。建议在修完 ①–⑦ 后看 ≥5 费的偏差是否收敛；若仍系统性为负，再另开 ADR 讨论公式是否改为 `1.8 × cost + 2` | 全部 12 张 ≥5 费偏弱卡 | 低（本次不作为改动依据） |

## §4 优先级（按顺序做前 5 项）

| 序 | 动作 | 理由 |
|---|---|---|
| **1** | 修 `transform` 定价：`(属性差) × 1.5 × 单位数 + 关键词差` | 一处改动同时解开高顺(+5.0)、马腾(+5.0)、公孙瓒(+5.0) 三张**同构卡**，并暴露"公孙瓒实际最超模"这个被现有指标看反的结论。**这是全表性价比最高的一刀** |
| **2** | 修 `damage`/`apply_status` 的 `count` 漏读 + `target.count: all` 按 3 目标计 | 张角(−3.2) 直接消解；陆逊(−7.3)、司马懿(−5.7) 各收回约 3 分；影响全卡池 14 张 AOE 卡，是**偏弱面 31 张的主要来源** |
| **3** | 把 `survive` 从 6 降到 3.5，并让 `skills[].chance` 参与 `skillValue` 折扣 | 周泰(+6.2) 与夏侯惇(+4.7) 的 77%/84% 偏差同源；顺带修掉"写在技能上的 `chance` 被忽略"这个与 `skills[].dsl` 同类的漏读 |
| **4** | `discard` 区分阵营（弃自己 = 0，弃对手 = 1.0/张）+ 补 `value_from_discarded` 定价 | 马谡(+6.0) 从 13.0 掉到 8.5（配合抽牌 2→1 正好 7.0 = 预算）；程昱(−3.5)、周瑜(−3.9) 的核心机制开始产生分数 |
| **5** | 单卡数据修：华雄合并双震慑 + `4/4→3/3`；左慈 `scry` 改指对手手牌 + `1/2→1/3` + 费用 4→3；郭嘉 / 司马懿 费用 6→5；陆逊费用 7→6；程普费用 5→6 | 这 6 张的偏差**不能只靠度量修**：华雄是数据重复结算，左慈是效果错译，郭嘉/司马懿/陆逊 1/4、1/6、1/5 的身材在 6–7 费位必须靠降费或补机制解决 |

## §5 不建议改的（含"改了会更糟"的）

| 卡 | 结论 | 理由 |
|---|---|---|
| `qun_zhangjiao` 张角 5 费 1/5 −3.2 | **不改**，只修 §3-① | `count: 5` 被漏读是**度量 bug**。修正后偏差 −1.15（1/5 身材 + 每回合 5 次 1 伤随机雷击 + 击杀转 1/1），恰好落在"高费低属性 + 强技能"的设计意图内。按现状的 7.8 分去涨费或加血，会做出真正的超模卡 |
| `qun_gaoshun` 高顺 4 费 2/2 +5.0 | **先不改**（度量修正后为 +4.0，再议） | 盾兵→陷阵盾兵只赚 +1 攻/只，`transform` 真值 3.0 被记 4.0。**若用错误的指标去砍它，会砍掉一张本来就不算强的卡**。等 §3-④ 修完再复核 |
| `qun_mateng` 马腾 4 费 2/2 +5.0 | **不改卡面**，交给 §3-④ | 同构卡，真值 15.0 vs 度量 14.0，方向一致（都是偏强），但"偏强多少"要把先攻（−1.0/只）算进去才知道，现在动数值是盲调 |
| `shu_zhugeliang` 诸葛亮 7 费 1/6 −4.0 | **不改卡面** | `ban_play` 锁对手手牌 + 每回合看牌库顶，是"控制型 7 费"的合理形态；它偏弱是 §3-⑤ 把 `ban_play` 定成 2.5 造成的。**不要因为分数低就给 1/6 加属性**——那会变成"高属性 + 强控"的双高卡 |
| `wei_chengyu` 程昱 5 费 1/5 −3.5 | **不改数值杠杆**（只补度量） | `design-review-SAB.md` 已判定为"低属性 + 强技能"路线 A 的样本，方向维持；`value_from_discarded` 记 0 分是度量缺口，补上后偏差回到 −2～−3，不需要动 1/5 |
| `qun_gongsunzan` 公孙瓒 | **改卡，但别按 +5.0 的幅度改**（仍计入"13 张建议改"） | 现有指标显示 +5.0，修正后实为 **+9.0**。建议只砍 `summon neutral_archer count: 2→1`（降 3 分 + 少一只进化底料）。**避免"照着 +5.0 把 2/2 砍成 1/1"**——那是砍错了方向，白马义从的强度在进化件上 |
