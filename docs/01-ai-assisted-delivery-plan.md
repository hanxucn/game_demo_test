# AI 重度辅助下的交付计划重估（v2）

> 前提修正：团队全程使用 AI Agent 承担编码、测试、数据管线、工具与文档。
> 本文细化并替代 `00-tech-selection.md` §6（前两周执行清单）与 §8（AI 辅助的边界），其余结论不变。

## 1. 先说结论

| 问题 | 回答 |
|---|---|
| AI 会不会显著提速？ | **会，但只压缩"写代码"，不压缩"等外部反馈"** |
| 原排期是否保守？ | **是，代码类工作我按 1x 估的，实际可到 2-3x** |
| 总工期能压多少？ | 同范围：10 周 → **7-8 周**；压范围：**6 周**可出可玩 demo |
| 最大收益是什么？ | 不是"更快"，而是**同时间内把内容量/打磨度/工具链抬一个台阶**（卡池 40→100+） |
| 什么完全压不动？ | 版号与审核、平台 SDK 真机联调、玩法手感与平衡的人类循环 |

**一句话**：AI 让"做得出"变容易了，但**没有让"做对了"变容易**。卡牌项目的瓶颈本来就偏后者。

## 2. 逐工作流的压缩系数（用于重排期）

| 工作流 | 原估（人周） | AI 后（人周） | 系数 | 说明 |
|---|---|---|---|---|
| core 规则引擎 + 效果 DSL | 4-6 | **2-3** | ~2x | 纯逻辑、有测试兜底，AI 最强区 |
| 数据管线（表→类型→校验） | 1 | **0.3** | ~3x | 样板代码 |
| 战斗表现层 + UI | 4-6 | **2-3** | ~2x | Cocos UI 代码 AI 友好；**动效手感仍需人调** |
| 内容（40-60 卡 + 关卡） | 3-4 | **1-1.5** | ~3x | 数据驱动后 AI 批量产出；**平衡仍需模拟+人审** |
| 后端（登录/存档/榜单/配置） | 3-4 | **1.5-2** | ~2x | Go 样板 AI 强 |
| **平台接入（微信/抖音 SDK/支付/广告/分享/开放数据域）** | 2-3 | **1.5-2.5** | **~1.2x** | **AI 弱**：官方文档私有细节、真机反馈慢、幻觉代价高 |
| **包体/性能/机型适配** | 1-2 | **1-2** | **~1x** | 需要真机测量闭环 |
| 工具链（卡牌编辑器/回放器/模拟器/埋点） | 2-3 | **0.5-1** | ~3x | AI 写内部工具极快，**杠杆最高的投入** |
| 合规/版号/审核 | — | — | **0x** | 纯外部，与 AI 无关 |
| 美术素材（占位→可用） | 2-3 | **1** | ~2.5x | 图像生成解决占位；一致性/风格统一仍受限 |

**注意**：系数不能简单相加——AI 产出量上升后，**评审与验收成为新瓶颈**（见 §5）。

## 3. 修正后排期（3 人 + AI）

### 3.1 推荐路线：8 周，范围不降反升

| 周 | 目标 | 验收标准（可度量） |
|---|---|---|
| **W0（3-4 天）** | **护栏周**（新增，不可省） | AGENTS.md / CI / lint / 测试框架 / 数据校验器 / 包体报告 / 回放器骨架 全部就位 |
| W0 并行 | 平台 Spike + 合规启动 | 小游戏真机跑通；首包 ≤4MB、冷启 <3s；软著/版号/备案启动 |
| W1-2 | **可玩闭环** | 单机一局能打完；golden replay 通过；**每日可玩构建** |
| W3-5 | 内容与表现 | 80-100 张卡、10-15 关、完整 UI、新手引导、存档 |
| W6-7 | 后端 + 平台 + 打磨 | 登录/存档/榜单/异步 PvP；广告分享接入；真机帧率与崩溃率达标 |
| W8 | 提审灰度 | 提审包 + 数据埋点 + 运营配置后台 |

### 3.2 激进路线：6 周（前提是范围锁定）

- 卡池 50 张、单机 PvE、无 PvP、占位美术升级为"可接受"而非"好看"；
- 前提：W0 护栏周做完、机制文档在 W0 前定稿、平台 Spike 一次通过；
- **任何一项不满足，就回到 8 周路线**。

### 3.3 什么情况下会退回到 10-12 周

- 平台 Spike 发现包体/性能不达标需要返工；
- 机制在 W3 之后还在大改（最常见的失败模式）；
- AI 产出缺少验收导致返工（§5）；
- 范围膨胀（AI 让加功能太便宜，这是**新风险**）。

## 4. AI 压不动的三件事（真正的关键路径）

1. **版号 / 备案 / 审核**：企业主体 + 内购 → 版号数月级，与开发并行但不可压缩。demo 阶段走体验版。
2. **平台 SDK 与真机循环**：微信/抖音的 Adapter 私有细节、iOS 真机表现、审核驳回反馈，全是慢反馈回路。AI 在这里只会"看起来很对"。
3. **玩法手感与平衡**：AI 能跑 10 万局出胜率表，但"这局打得爽不爽"必须人类玩。这是墙钟时间，不是算力。

## 5. AI 重度开发的新风险（原计划未覆盖）

| 风险 | 表现 | 对策 |
|---|---|---|
| **验收债** | 日产出 5000 行，团队只能审 500 行 | 小 PR + 必须带测试；"无测试不合并"；核心模块覆盖率门槛 |
| **幻觉 API** | 平台 SDK / 引擎版本 API 编造 | 仓库内存官方文档片段 + `verified-snippets/`；AI 只能引用已验证片段 |
| **规则漂移** | AI 把规则实现成"看起来合理"的版本 | 机制写成**可执行 spec**（不变量 + 边界用例），golden replay 做回归 |
| **范围膨胀** | 加功能太便宜 → 什么都想加 | W0 冻结范围清单；新需求进 backlog 不进 v1 |
| **架构腐蚀** | AI 跨模块乱改、隐式耦合 | 明确模块边界 + 依赖方向检查；`core` 零引擎依赖是硬约束 |
| **上下文退化** | 大文件/大仓库里 AI 改错 | 小文件、单一职责、AGENTS.md 说明；避免 2000 行以上的脚本 |

## 6. 让 AI 杠杆最大化的工程实践（W0 护栏周清单）

- [ ] **规格即契约**：机制文档 → 数据结构 + 不变量 + 边界用例，AI 从 spec 生成实现与测试
- [ ] **数据驱动到位**：加一张卡 = 只改 YAML，**不写代码**（这是 AI 杠杆是否生效的判据）
- [ ] **回放即回归**：每局生成 replay，改动后历史 replay 必须仍可一致重放
- [ ] **一效果一测试**：效果 DSL 让 AI 批量生成用例
- [ ] **构建即验收**：CI 每次产出小游戏包 + 包体报告 + 冷启基线，超限直接 fail
- [ ] **平台层文档驱动**：`docs/platform/wx/*.md` 存官方文档片段，禁止 AI 凭记忆写 SDK
- [ ] **内部工具优先**：卡牌编辑器、回放器、平衡模拟器——AI 写工具最快，且能乘数放大后续所有工作
- [ ] **双人复核**：AI 写、另一人审 + 跑测试，禁止"AI 写完直接合"

## 7. 跟踪指标（判断是否真的在加速）

| 指标 | 目标 | 含义 |
|---|---|---|
| 每日可玩构建 | 100% | 项目节律的底线 |
| 新增一张卡的边际成本 | **趋近"只写数据"（<30 分钟）** | AI 杠杆是否真正生效的核心判据 |
| golden replay 通过率 | 100% | 规则未被 AI 改坏 |
| 首包体积趋势 | ≤4MB 且不反弹 | 小游戏生死线 |
| 真机冷启 / 帧率 | <3s / ≥50fps | 平台体验 |
| PR 平均评审时长 | <4 小时 | 验收债是否累积 |

## 8. 团队分工（AI 下的调整）

| 角色 | 职责 | AI 用法 |
|---|---|---|
| 前端 = **集成/架构负责人** | 接口定义、平台接入、构建与包体、评审闸门 | AI 写 UI 与工具；平台 SDK 人工核文档 |
| 后端 A = **玩法负责人** | core 规则、效果 DSL、数据管线、平衡模拟 | AI 批量产出卡牌与测试；人定机制与手感 |
| 后端 B = **服务端/合规负责人** | Go 服务、埋点、支付链路 + **版号/备案推进** | AI 写后端样板与内部工具 |

> AI 时代 3 人团队最稀缺的不是"能写代码的人"，而是**能定义接口、能验收、能守住范围的人**。

## 9. 对 Godot 结论的再审视（AI 视角）

AI 确实降低了 Godot 小游戏适配的**写代码成本**（估算从 1.5-3 人月降到 0.5-1.5 人月），但：

- **降低的是均值，不是方差**：真正的风险是"撞上无法绕过的平台限制"（wasm 体积、低端机性能、开放数据域缺失），这类问题 AI 无法替你解决；
- **你们的窗口是 6-8 周**，此时方差比均值重要得多；
- Godot 侧确有 AI 工具（社区 MCP、[godot-minigame](https://github.com/godothub/godot-minigame) 仓库自带 `skills/` 供 AI 做适配），Cocos 侧是官方 AI-Native 路线（MCP/Agent 优先）——**两边都有 AI 杠杆，不构成选型差异**。

**结论不变：v1 用 Cocos。** 若仍想验证 Godot，把 §3 的 W0 Spike 照做，用数据决定，别用感觉决定。
