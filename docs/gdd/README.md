# 《酒话三国》机制设计文档

> 版本 v0.1（机制骨架）· 平台：微信/抖音小游戏（横屏）· 引擎：Cocos Creator 3.8 LTS + TypeScript

## 这套文档是什么

这是《酒话三国》的**唯一机制真源**。任何一张卡、一个状态、一次结算，都以本文档为准。
文档的设计目标是：**能被直接翻译成数据文件，不需要再回来问"这个怎么算"**。

## 术语表

| 术语 | 英文 | 定义 |
|---|---|---|
| 主公 | Lord | 玩家的化身，30 HP，不参与普通攻击，拥有一个主动技 |
| 统率值 | Command | 唯一资源，初始 1、每回合 +1、上限 10 |
| 护甲 | Armor | 附加于主公的伤害缓冲，永久保留、优先于生命被扣除 |
| 人物卡 | Character | 会留在场上、拥有攻/血属性的卡（兵种卡、武将卡、谋臣卡） |
| 非人物卡 | Non-character | 一次性结算的卡（事件卡、战法卡、特殊兵种卡） |
| 前军 / 后军 | Front / Back Row | 每方两排，每排 5 格 |
| 列 | Lane | 1–5，从玩家视角自左向右编号；双方列号在屏幕上对齐 |
| 同列 | Same Lane | 双方屏幕位置相同的列 |
| 穿透 | Piercing | 目标列前军为空时，近战可攻击该列后军 |
| 架盾 | Shield Wall | 关键词：全局嘲讽，仅前军生效，必须先被击破 |
| 神射 | Marksmanship | 关键词：可攻击任意列的人物卡 |
| 先攻 | First Strike | 关键词：先结算伤害，目标阵亡则不受反击 |
| 无双 | Peerless | 关键词：攻击时不受到反击伤害 |
| 粮尽 | Starvation | 牌库抽空后每次抽牌的递增伤害 |

## 与《炉石传说》的核心差异

| 维度 | 炉石 | 酒话三国 |
|---|---|---|
| 战场 | 单排 7 格 | **5 列 × 2 排 = 10 格** |
| 攻击范围 | 任意目标（除嘲讽） | **近战只能打同列；弓箭手可跨列** |
| 嘲讽 | 全局嘲讽，任何位置生效 | **架盾仅前军生效，且不阻挡对主将的攻击** |
| 主将保护 | 靠嘲讽 | **靠阵型：需清空一整列才能攻击主将** |
| 兵种 | 无 | **步兵/盾兵/弓箭手，各有专属关键词** |
| 升级 | 无 | **特殊兵种卡可将场上兵种进化为精锐** |
| 事件 | 无 | **事件卡对双方同时生效（天道无情）** |
| 开局 | 换牌 + 硬币 | **换牌 + 三选一酒令 + 掷先手** |
| 羁绊 | 无 | **同场羁绊 + 对抗羁绊** |

## 卖点清单（产品层面）

1. **历史人物卡牌**——四阵营 + 主公 + 武将 + 谋臣，靠关键词与技能形成辨识度
2. **事件卡与战法卡**——三国历史事件与兵法，对双方生效的"天道"设计
3. **随机性与不确定感**——天时（事件）、地利（阵型）、人和（羁绊）三轴
4. **人物组合**——同场羁绊与对抗羁绊，构筑与收集的核心驱动力
5. **破阵斩将**——清空一列才能打主公，三国战场的空间感

## 内容产能原则（工程约束）

> **加一张新卡的边际成本 = 只改数据文件。**

若任何一张卡需要写代码才能实现，说明数据模型或效果 DSL 需要扩展，而不是加特例。
这条原则决定了本项目的工程架构（见 `docs/00-tech-selection.md` 与 `docs/01-ai-assisted-delivery-plan.md`）。

## 状态标记约定

- **已定**：可以直接进入实现
- **草案**：机制成立，数值或细节待确认
- **待填**：等待策划提供内容（人物卡、事件卡、战法卡具体设计）
- **待调**：数值超出/低于预算，需要在实机测试中调整
