# 02 · 战场与攻击规则

> 状态：**已定**。本文件是整个游戏的规则地基，所有卡牌效果都在这套规则上叠加。

## 1. 战场结构

每方 **5 列 × 2 排 = 10 格**，主将位于本方阵型的**最远端**（阵型之后，不占格）。

**从外到内的空间顺序**（以我方视角，屏幕从上到下）：

```
敌 主 公  →  敌 后 军  →  敌 前 军  →  ══中线══  →  我 前 军  →  我 后 军  →  我 主 公
   最远                                            最远
```

```
                          ┌──────────┐
                          │ 敌 主 公 │   ← 敌最远端
                          └──────────┘
                    ┌────┬────┬────┬────┬────┐
        敌 后 军 →  │    │    │    │    │    │
                    ├────┼────┼────┼────┼────┤
        敌 前 军 →  │    │    │    │    │    │
                    └────┴────┴────┴────┴────┘
        ══════════════════════════════════════════
                    ┌────┬────┬────┬────┬────┐
        我 前 军 →  │    │    │    │    │    │
                    ├────┼────┼────┼────┼────┤
        我 后 军 →  │    │    │    │    │    │
                    └────┴────┴────┴────┴────┘
                          ┌──────────┐
                          │ 我 主 公 │   ← 我最远端
                          └──────────┘
                    ↑    ↑    ↑    ↑    ↑
                   列1  列2  列3  列4  列5
```

**进攻路径**：我方某列的人物卡 → 该列敌方前军 → 该列敌方后军 → **敌方主公**。
因此"清空一列"= 击破该列的**前军与后军两排**，之后才能沿该列直取敌方主公。

### 坐标系统

- **列（Lane）**：1–5，从玩家视角自左向右编号；**双方的列号在屏幕上对齐**（我方列 3 正对敌方列 3）
- **排（Row）**：`前军` / `后军`
- **格（Slot）**：`(列, 排)`，例如 `(3, 前军)`
- **同列**：双方屏幕位置相同的列，即"正对面"

### 格子容量

| 项 | 规则 |
|---|---|
| 每格 | 最多 1 张人物卡 |
| 每方上限 | 10 张人物卡 |
| 空格 | 属于正常状态，空格构成"穿透"与"破阵"的基础 |

## 2. 部署规则

| 项 | 规则 |
|---|---|
| 落牌位置 | 可放在**己方任意空格**（前军或后军，任意列） |
| 近战放后军 | 允许，但会被己方前军挡住而无法攻击（自然惩罚，见 §3.2） |
| 满格 | 场上无空格时不能部署新人物卡 |
| 入场当回合 | **不能攻击**（「疾行」除外），但可以触发"入场"技能 |
| 入场触发 | 按"战吼/入场"结算，时机见 `10-skills-statuses.md` 结算时机表 |

## 3. 普通攻击

### 3.1 谁能攻击

| 卡类 | 能否普通攻击 |
|---|---|
| 兵种卡（步兵/盾兵/弓箭手） | ✅ |
| 武将卡 | ✅ |
| 谋臣卡 | ❌ 永远不能普通攻击（靠技能输出） |
| 主将 | ❌ 只有主动技 |
| 被「震慑」的人物 | ❌ 不能攻击，也不能使用主动技 |
| 当回合入场的人物 | ❌（「疾行」除外） |
| 已攻击过的本回合 | ❌（「连击」允许 2 次） |

### 3.2 近战攻击目标（步兵、盾兵、武将）

按以下**优先级顺序**判定合法目标：

```
① 场上存在敌方「架盾」人物卡？
   → 目标必须是架盾人物卡（可跨列，无视同列限制）★ 架盾是唯一例外
② 否则：攻击者所在列的敌方前军有人物卡？
   → 目标是它
③ 否则：攻击者所在列的敌方后军有人物卡？
   → 目标是它（穿透）
④ 否则（该列两排皆空）：
   → 目标可以是敌方主将
```

**被自己人挡住**：若攻击者位于后军，且其正前方同列有**友方**人物卡，则**无法发动普通攻击**（近战路径被己方挡住）。
> 弓箭手不受此限制（见 §3.3）；此规则让"把近战放后军"成为明确的错误选择。

### 3.3 远程攻击目标（弓箭手「神射」）

```
① 场上存在敌方「架盾」人物卡？
   → 目标必须是架盾人物卡（架盾优先级高于神射）
② 否则：可攻击任意列的敌方人物卡（无视距离与同列限制）
③ 攻击主将：仍需满足"攻击者所在列两排皆空"（主将保护见 §4）
```

> **神射的价值是"跨列施压"**：近战必须站在对应列才能攻击，弓箭手不需要。
> 神射**不能**绕过架盾——否则盾兵失去意义。

### 3.4 攻击结算顺序

一次普通攻击按以下顺序结算：

```
1. 攻击者 → 目标：造成等同于攻击者攻击力的伤害
2. 若目标为人物卡且存活 → 目标反击：对攻击者造成等同于目标攻击力的伤害
3. 例外：
   · 攻击者有「先攻」→ 先结算第 1 步；若目标阵亡，则跳过第 2 步（不受反击）
   · 攻击者有「无双」→ 跳过第 2 步（不受反击）
   · 目标为主将 → 主将不反击
4. 伤害结算（护甲/免疫/武圣等修正）→ 见 `10-skills-statuses.md`
5. 死亡结算：血量 ≤ 0 的人物卡移出战场，触发「忠义/遗计」等亡语
```

## 4. 主将保护（破阵斩将）

| 项 | 规则 |
|---|---|
| 攻击主将的条件 | ① 场上无敌方架盾人物卡；② **攻击者所在列的两排皆空** |
| 为什么 | 让"破阵"成为核心战术目标，而不是无脑打脸 |
| 主将反击 | 无 |
| 主将受伤 | 先扣护甲，护甲为 0 后扣生命 |
| 主将阵亡 | 生命 ≤ 0 → 该方立即失败 |

> **战术推论**：主将位于最远端，因此**某一列的后军是主将在该列的最后一道防线**。
> 后军被清空后，该列只剩前军作为屏障；两排皆空时该列即被"打穿"，敌方沿此列直取主将。
> 这意味着"往受威胁的列补一个廉价单位"是有效的防守手段（补空列 / lane denial）。

### 4.1 三泄压阀（防止对局拖死）

主将保护会拖慢节奏，因此设计三个泄压阀：

1. **计谋直伤**：谋臣的主动技、战法卡、事件卡**可以直接伤害主将**（无视阵型保护）——"计谋伤人"
2. **粮尽**：牌库抽空后，每回合抽牌时受到递增伤害（1、2、3…）
3. **破阵奖励**：清空一列后，该列的攻击者在本回合获得 +1 攻击（鼓励破阵）

## 5. 架盾（盾兵的全局嘲讽）

| 项 | 规则 |
|---|---|
| 生效条件 | **仅当盾兵位于前军时生效**；位于后军则失去架盾 |
| 效果 | 敌方任何普通攻击**必须先攻击架盾人物**（可跨列） |
| 优先级 | 高于同列限制、高于「神射」 |
| 对主将 | **架盾不阻挡对主将的攻击**（主将的保护由阵型负责） |
| 破盾手段 | ① 直接击杀架盾人物；② **谋臣的计略伤害无视架盾**；③ 战法/事件卡 |
| 多个架盾 | 存在多个架盾人物时，攻击者可任选其一作为目标 |

> **设计意图**：架盾保护的是**将士**（挡住敌方点杀你的谋臣、残血武将），而不是主公。
> 主将由阵型保护。两种保护各司其职，避免"双层护盾"把对局拖死。

## 6. 列数权衡（决策记录 ADR-001）

### 背景

主将可被攻击的条件是"攻击者所在列两排皆空"。防守方要封死所有列，至少需要 **N 个单位**（N = 列数），而受统率限制，实战场上通常只有 3–6 个单位。

### 结论

| 列数 | 封死所需单位 | 节奏倾向 |
|---|---|---|
| 4 列 | 4 | 偏慢、偏控制 |
| **5 列（采用）** | 5 | **居中** |
| 6 列 | 6 | 偏快、偏铺场 |

- **采用 5 列 × 2 排**：节奏居中，配合 30 HP + 6–8 分钟目标；
- "补空列"（lane denial）成为核心技巧：1 费的 2/1 步兵不只是站场，还是堵隘口的工具；
- 6 列在横屏下 UI 同样可行，作为**可选方案**保留（若实测对局过慢可改）。

### 降级预案

若真机测试发现 5 列在部分机型上可读性不足 → 退回 4 列 × 2 排，并把主公生命降至 25 以补偿节奏。

## 7. UI 约束（横屏）

| 项 | 约束 |
|---|---|
| 方向 | 横屏（`game.json` → `deviceOrientation: "landscape"`） |
| 设计基准 | 736 × 414（微信 `displayMode: mobile`） |
| **适配策略** | **fit-height（高度铺满）+ 宽度自适应**；横向 5 列用 Widget 百分比布局，不写死像素宽 |
| 每列宽度 | 约 140pt（设计尺寸）；物理宽度随屏幕变化：iPhone SE 约 127px → iPad 约 191px |
| 卡面内容 | 卡名（≤4 字）+ 攻/血数字 + 关键词图标；**不在卡面放描述文字** |
| 关键词说明 | 长按/点击卡牌弹出详情面板 |
| 状态显示 | 图标 + 层数角标；异常状态用红色描边 |
| 列高亮 | 悬停/选中时高亮该列的合法目标 |
| **最小机型风险** | iPhone SE / 12 mini 横屏（375pt 高）下兵阵卡约 **127 × 51 px**，卡名 11.8px、数值 10.9px——可读但无余量，**必须真机验证** |
| **手牌补偿** | 最小机型手牌卡仅 56 × 65 px，需**点按放大预览** |
| 降级方案 | 若真机反馈卡面过挤 → 设计高度改 375 + 紧凑单行卡面（行高 46pt） |

> 实测数据与交互原型见 `prototype/README.md` 与 `prototype/battlefield-wireframe.html`。
